# Making Candies

來源教材：`docs/algorithm/hackerrank-interview-kit-kotlin/07-search.md`

官方題目：[Making Candies](https://www.hackerrank.com/challenges/making-candies/problem)

### 中文題意

機器數 m、工人數 w，每回合產 m*w 糖；可花 p 買一台機器或一名工人，求達到 n 的最少回合。

### 中文重點摘要

先快轉到買得起，購買時平衡 m、w 才讓乘積最大。

### 最佳解題思路

每次比較「完全不買直接完成」與「快轉、購買、平衡後繼續」；買時先補較小的一側，再平分剩餘購買力。

### 正確性理由

總和固定時乘積在兩數最接近時最大；快轉不改變任何可做決策，只略過無法購買的回合。

### 複雜度

時間約 `O(log n)` 個購買階段；空間 `O(1)`。

### Kotlin 範例程式

```kotlin
fun minimumPasses(m0: Long, w0: Long, p: Long, n: Long): Long {
    var m = m0; var w = w0; var candies = 0L; var rounds = 0L; var best = Long.MAX_VALUE
    while (candies < n) {
        val rate = m * w
        best = minOf(best, rounds + (n - candies + rate - 1) / rate)
        if (candies < p) { val skip = (p - candies + rate - 1) / rate; rounds += skip; candies += skip * rate; continue }
        var buy = candies / p; candies %= p
        if (m < w) { val add = minOf(buy, w - m); m += add; buy -= add } else { val add = minOf(buy, m - w); w += add; buy -= add }
        m += buy / 2; w += buy - buy / 2; rounds++ ; candies += m * w
    }
    return minOf(best, rounds)
}
```

### 走讀與常見錯誤

不可每回合只買機器，m、w 失衡會浪費產能。此題所有乘法必須使用 Long。
