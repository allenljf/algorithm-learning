# Design Twitter

來源教材：`docs/algorithm/neetcode150/04-補齊63題詳解.md`

**題意摘要：** 在 `Heap / Priority Queue` 的限制下，從輸入建立足以判定結果的狀態；這裡刻意只描述學習目標，不重製第三方題面。

**演算法：** 先選擇能保留關鍵不變量的 `Heap / Priority Queue` 資料結構或狀態轉移；每一次更新都排除不可能的候選，最後以狀態是否滿足目標判定答案。

**Kotlin 解法：** [`X355`](checks/ExtraSolutions.kt) 是本題獨立實作。先用小案例走讀狀態，再比較程式中的更新條件。

**複雜度：** 時間 O(n log n)；空間 O(n)。

**常見錯誤：** 把狀態更新與檢查順序顛倒，或漏掉空集合、單一元素、重複值與邊界座標。

**自建案例：** 驗證器為本題執行一個一般案例與一個邊界／反例；兩者皆不是第三方題面範例。

### Kotlin 範例程式

```kotlin
class X355 { private data class T(val t:Int,val u:Int,val id:Int);private var clock=0;private val follows=HashMap<Int,MutableSet<Int>>();private val tweets=HashMap<Int,MutableList<T>>();fun postTweet(u:Int,id:Int){tweets.getOrPut(u){mutableListOf()}.add(T(++clock,u,id))};fun getNewsFeed(u:Int)=((follows[u]?:emptySet())+u).flatMap{tweets[it]?:emptyList()}.sortedByDescending{it.t}.take(10).map{it.id};fun follow(a:Int,b:Int){follows.getOrPut(a){mutableSetOf()}.add(b)};fun unfollow(a:Int,b:Int){follows[a]?.remove(b)} }
```
