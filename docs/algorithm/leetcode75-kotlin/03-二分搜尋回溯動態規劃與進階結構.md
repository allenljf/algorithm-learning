先認識五個詞：

- **二分搜尋**：每次用一個判斷，排除一半候選答案。重點是你有沒有理由確定被丟掉的那半邊不必再看。
- **回溯**：先做一個選擇，走下去，回來時撤銷，再試另一個選擇。像試穿衣服，試下一件前要先脫下上一件。
- **動態規劃（DP）**：把小問題的答案記下來，大問題直接使用已算好的答案。最重要的問題是「這個格子到底代表什麼？」
- **貪心**：每一步選一個當下最有利的選項；但必須解釋這個選擇為什麼不會害後面失去最佳解。
- **單調堆疊**：一疊尚未解決的項目，另外維持由大到小或由小到大的順序，讓新資料能一次解決一批舊項目。

## 374. Guess Number Higher or Lower

**難度：Easy｜觀念：二分搜尋**
[英文原題](https://leetcode.com/problems/guess-number-higher-or-lower/) · [官方中文](https://leetcode.cn/problems/guess-number-higher-or-lower/)

### 中文題意與輸入輸出

對方選好 `1..n` 之間的一個整數，你只收到 `n`，不能直接讀取答案。平台提供 `guess(x)`：回傳 `-1` 表示你猜太大，`1` 表示太小，`0` 表示正確。請回傳猜中的數字。`n` 最大是 `Int.MAX_VALUE`，答案保證存在。

### 白話思路與手算

從 1 一個個試，最壞要試 n 次。猜中間值就能直接排除半邊：如果中間值都太小，左邊那些更小的值一定也錯。

原創例：`n=20`，平台藏的是 `14`。

```text
候選 1..20  → 猜10 → 太小 → 剩11..20
候選11..20  → 猜15 → 太大 → 剩11..14
候選11..14  → 猜12 → 太小 → 剩13..14
候選13..14  → 猜13 → 太小 → 剩14..14
候選14..14  → 猜14 → 正確
```

`left`、`right` 都包含在候選範圍內。猜錯的 `mid` 不可能是答案，所以更新時可以跨過它。每一輪仍保證真正答案留在候選區間。

### Kotlin 解答

`GuessGame` 和 `guess()` 由 LeetCode 提供；本題不需要自行寫讀取標準輸入的程式。

```kotlin
class Solution : GuessGame() {
    fun guessNumber(n: Int): Int {
        var left = 1
        var right = n
        while (left <= right) {
            val mid = left + (right - left) / 2
            when (guess(mid)) {
                0 -> return mid
                -1 -> right = mid - 1 // 猜太大
                1 -> left = mid + 1   // 猜太小
            }
        }
        return -1 // 題目保證有答案，正常不會走到這裡
    }
}
```

`guess()` 的正負號方向不能更換。本機驗證時需另提供模擬 `GuessGame`，平台提交則使用題目提供的基底類別。

**複雜度：** 時間 `O(log n)`、額外空間 `O(1)`，n 是最大可猜的數字。

**常見錯誤：** `(left + right) / 2` 可能溢位；把 `-1` 誤認為要往更大的方向猜；忘記跨過已確定錯誤的中點而無限迴圈。

**理解自測：** 如果猜 8 得到 -1，8 要留在下一輪嗎？
**答案：** 不用；答案嚴格小於 8，所以右界變 7。

## 2300. Successful Pairs of Spells and Potions

**難度：Medium｜觀念：排序、尋找第一個符合條件的位置**
[英文原題](https://leetcode.com/problems/successful-pairs-of-spells-and-potions/) · [官方中文](https://leetcode.cn/problems/successful-pairs-of-spells-and-potions/)

### 中文題意與輸入輸出

輸入咒語強度 `spells`、藥水強度 `potions` 和門檻 `success`。咒語乘藥水大於等於門檻即成功。回傳每個咒語能和幾瓶藥水成功配對，輸出順序必須和咒語相同。兩個陣列各有 1–100,000 個正整數，強度最多 100,000；門檻最多 10¹⁰，必須使用 `Long`。

### 白話思路與手算

每個咒語掃遍所有藥水，會做 n×m 次乘法。先把藥水由小到大排好；因為咒語是正數，乘積也跟著由小到大。只要找到第一瓶成功的藥水，後面全部成功。

原創例：`spells=[2,4]`、`potions=[5,1,3]`、`success=10`。

```text
排序後藥水：    1  3  5
咒語2的乘積：  2  6 10 → 第一個成功在索引2 → 3-2=1瓶
咒語4的乘積：  4 12 20 → 第一個成功在索引1 → 3-1=2瓶
輸出：[1,2]
```

搜尋區間採 `[left,right)`，右邊不包含。初始化 `right=m`，若全部失敗，最後位置就是 m，`m-m=0`。成功時保留 mid 當可能的第一個位置，不能用 `mid-1`。

### Kotlin 解答

```kotlin
class Solution {
    fun successfulPairs(spells: IntArray, potions: IntArray, success: Long): IntArray {
        val sorted = potions.sortedArray() // 保留原始輸入
        val answer = IntArray(spells.size)
        for (i in spells.indices) {
            var left = 0
            var right = sorted.size
            while (left < right) {
                val mid = left + (right - left) / 2
                if (spells[i].toLong() * sorted[mid] >= success) {
                    right = mid
                } else {
                    left = mid + 1
                }
            }
            answer[i] = sorted.size - left
        }
        return answer
    }
}
```

**複雜度：** n 是咒語數、m 是藥水數。時間 `O(m log m + n log m)`；額外空間 `O(m)`，另有 `O(n)` 輸出。

**常見錯誤：** 乘完才 `.toLong()` 已經太晚，溢位發生在乘法當下；把 `>=` 寫成 `>` 會漏掉剛好達標的配對。

**理解自測：** 第一個成功位置是 0，表示什麼？
**答案：** 最小的藥水都成功，因此全部 m 瓶都成功。

## 162. Find Peak Element

**難度：Medium｜觀念：利用上坡方向二分**
[英文原題](https://leetcode.com/problems/find-peak-element/) · [官方中文](https://leetcode.cn/problems/find-peak-element/)

### 中文題意與輸入輸出

輸入非空整數陣列，找一個比左右鄰居都大的元素，回傳其**索引**。可以有多個山峰，回傳任一個。陣列外側想像成負無限大，相鄰元素保證不相等。長度 1–1000，數值可涵蓋全部 Int；題目要求 `O(log n)`。

### 白話思路與手算

線性掃描能找到，但不符合時間要求。看中間位置和右邊鄰居：若右邊比較高，就往右邊找山峰。因為沿上坡往右，遲早會開始下坡，或一路走到邊界；這兩種情況都會出現山峰。若右邊較低，mid 本身或它左邊一定有峰。

原創例 `[2,5,9,6,3]`：

```text
索引：0 1 2 3 4
數值：2 5 9 6 3
          ^ mid=2，9>6 → 搜尋0..2
mid=1，5<9 → 搜尋2..2 → 答案索引2
```

陣列不需要排序。這裡不是尋找某個值，而是維持「目前範圍裡至少還有一座峰」的保證。

### Kotlin 解答

```kotlin
class Solution {
    fun findPeakElement(nums: IntArray): Int {
        var left = 0
        var right = nums.lastIndex
        while (left < right) {
            val mid = left + (right - left) / 2
            if (nums[mid] < nums[mid + 1]) left = mid + 1
            else right = mid
        }
        return left
    }
}
```

**複雜度：** n 是陣列長度；時間 `O(log n)`，額外空間 `O(1)`。

**常見錯誤：** 回傳高度而非索引；以為題目要全域最大值；使用 `left<=right` 卻仍讀 `mid+1`，可能越界。

**理解自測：** `[8,6,4]` 的峰在哪裡？
**答案：** 索引 0。左邊界外視為負無限大，所以 8 滿足條件。

## 875. Koko Eating Bananas

**難度：Medium｜觀念：對答案二分搜尋**
[英文原題](https://leetcode.com/problems/koko-eating-bananas/) · [官方中文](https://leetcode.cn/problems/koko-eating-bananas/)

### 中文題意與輸入輸出

輸入每堆香蕉數 `piles` 與時限 h。每小時只吃一堆，最多吃 k 根；該堆不足 k 根也要用完整一小時，不能把剩下時間拿去吃另一堆。求能在 h 小時內吃完的最小整數速度 k。堆數 1–10,000，每堆最多 10⁹；h 至少等於堆數，最多 10⁹。

### 白話思路與手算

先別問「最佳速度是多少」，先問「給定速度，能吃完嗎？」每堆花 `ceil(數量/k)` 小時。速度越快只會越容易完成，所以可行性排列成「不行、不行、可以、可以」，適合找第一個可以。

原創例 `piles=[4,8]`，`h=4`：

```text
k=2：2+4=6小時，不行
k=3：2+3=5小時，不行
k=4：1+2=3小時，可以 → 最小速度4
```

最大一堆的數量一定是可行上限：這個速度每堆只花一小時。使用整數公式 `(p+k-1)/k` 向上取整；加法與總時數都用 Long，避免大資料溢位。

### Kotlin 解答

```kotlin
class Solution {
    fun minEatingSpeed(piles: IntArray, h: Int): Int {
        var left = 1
        var right = piles.maxOrNull()!!
        while (left < right) {
            val mid = left + (right - left) / 2
            var hours = 0L
            for (pile in piles) {
                hours += (pile.toLong() + mid - 1) / mid
            }
            if (hours <= h.toLong()) right = mid
            else left = mid + 1
        }
        return left
    }
}
```

**複雜度：** n 是堆數、M 是最大一堆數量；時間 `O(n log M)`，額外空間 `O(1)`。

**常見錯誤：** 用香蕉總數除以 h，忽略每堆各自佔用整小時；把可行時的 mid 排除，錯過最小速度。

**理解自測：** 當 h 就等於堆數，答案是多少？
**答案：** 最大一堆數量。每堆都只能花一小時。

## 17. Letter Combinations of a Phone Number

**難度：Medium｜觀念：回溯列舉**
[英文原題](https://leetcode.com/problems/letter-combinations-of-a-phone-number/) · [官方中文](https://leetcode.cn/problems/letter-combinations-of-a-phone-number/)

### 中文題意與輸入輸出

輸入由 2–9 組成的字串，依電話鍵盤把每個數字換成對應的一個英文字母，列出所有組合。2 對 abc、3 對 def、4 對 ghi、5 對 jkl、6 對 mno、7 對 pqrs、8 對 tuv、9 對 wxyz。查閱時英文頁限制長度 1–4；程式亦兼容舊題面可能出現的空字串，回傳空清單。

### 白話思路與手算

先替第一格選字母，再替第二格選，直到每格都有字母就記錄。回來時要撤銷剛才的選擇，否則下一個分支會夾帶上一個答案。

原創例 `digits="24"`：

```text
空字串
├─a → ag、ah、ai
├─b → bg、bh、bi
└─c → cg、ch、ci
```

`index` 表示正在填第幾格，`path` 是目前填好的字母。每層只處理自己的一格，因此不漏掉組合，也不會重複。這題要求輸出全部答案，指數級答案量無法靠神奇技巧消除。

### Kotlin 解答

```kotlin
class Solution {
    fun letterCombinations(digits: String): List<String> {
        if (digits.isEmpty()) return emptyList()
        val letters = arrayOf("", "", "abc", "def", "ghi", "jkl", "mno", "pqrs", "tuv", "wxyz")
        val result = mutableListOf<String>()
        val path = StringBuilder()
        fun dfs(index: Int) {
            if (index == digits.length) {
                result.add(path.toString())
                return
            }
            for (ch in letters[digits[index] - '0']) {
                path.append(ch) // 選
                dfs(index + 1) // 往下一格
                path.deleteCharAt(path.length - 1) // 撤銷
            }
        }
        dfs(0)
        return result
    }
}
```

**複雜度：** d 是數字長度；最多 4ᵈ 個答案，每個答案複製 d 個字元，時間 `O(d·4ᵈ)`；排除輸出，遞迴與路徑空間 `O(d)`，輸出 `O(d·4ᵈ)`。

**常見錯誤：** 忘記撤銷；把 `digits[index].toInt()` 當成數字 2，它其實是字元編碼。減 `'0'` 才會得到對應數字。

**理解自測：** `"79"` 有幾個答案？
**答案：** 4×4=16 個，因為兩個鍵各有四個字母。

## 216. Combination Sum III

**難度：Medium｜觀念：回溯、避免重複組合**
[英文原題](https://leetcode.com/problems/combination-sum-iii/) · [官方中文](https://leetcode.cn/problems/combination-sum-iii/)

### 中文題意與輸入輸出

從數字 1–9 裡選 k 個不同的數字，總和要等於 n，回傳所有選法。同一組不能因順序不同而重複出現。`2<=k<=9`，`1<=n<=60`。

### 白話思路與手算

原創例 `k=2,n=8`，答案是 `[[1,7],[2,6],[3,5]]`。`[4,4]` 不合法，因為不能重複取數字。

```text
先選1 → 下一個只試2..9 → 取7成功
先選2 → 下一個只試3..9 → 取6成功
先選3 → 下一個只試4..9 → 取5成功
先選4 → 下一個從5開始，總和至少9 → 不可能
```

選了 x 之後，下層從 x+1 開始，就自然保證數字不重複、排列只出現遞增版本。`remaining` 是還差多少，`path.size` 是已選幾個。數字都為正，因此 x 超過 remaining 後，更大的數字也不用試，這叫「剪枝」。

### Kotlin 解答

```kotlin
class Solution {
    fun combinationSum3(k: Int, n: Int): List<List<Int>> {
        val result = mutableListOf<List<Int>>()
        val path = mutableListOf<Int>()
        fun dfs(start: Int, remaining: Int) {
            if (path.size == k) {
                if (remaining == 0) result.add(path.toList())
                return
            }
            for (x in start..9) {
                if (x > remaining) break
                path.add(x)
                dfs(x + 1, remaining - x)
                path.removeAt(path.lastIndex)
            }
        }
        dfs(1, n)
        return result
    }
}
```

**複雜度：** 用候選數量 U 表示（本題固定 U=9），粗略上界時間 `O(U·2^U)`，包含結果複製；遞迴和路徑 `O(k)`，另加輸出。固定 9 不代表應該無視回溯的成長方式。

**常見錯誤：** `result.add(path)` 存入同一個可變清單，後面撤銷時答案也被改掉；要複製成 `path.toList()`。

**理解自測：** 為什麼下一層不是從 1 開始？
**答案：** 從 1 開始會重複使用數字，也可能同時產生 `[1,7]` 和 `[7,1]`。

## 1137. N-th Tribonacci Number

**難度：Easy｜觀念：DP 入門、滾動變數**
[英文原題](https://leetcode.com/problems/n-th-tribonacci-number/) · [官方中文](https://leetcode.cn/problems/n-th-tribonacci-number/)

### 中文題意與輸入輸出

數列的前三個值是 0、1、1，之後每個值等於前面三個值相加。輸入索引 n，回傳該位置的值。`0<=n<=37`，答案保證放得進 Int。

### 白話思路與手算

用遞迴直接寫「前一項＋前兩項＋前三項」會重複計算很多次。像 T(8) 和 T(7) 都要 T(6)，沒有必要算兩遍。

**狀態：** T(i) 是第 i 項。**初始值：** T(0)=0、T(1)=T(2)=1。**轉移：** T(i)=T(i−1)+T(i−2)+T(i−3)。**方向：** i 從 3 往 n 算，因為前面的答案要先有。

原創例 `n=5`：

```text
i：   0 1 2 3 4 5
T(i)：0 1 1 2 4 7
算5時只需1、2、4 → 7
```

既然每次只看最後三項，就不用保存整張表。a、b、c 像三張便條紙，每算出 next 就向前移一格。

### Kotlin 解答

```kotlin
class Solution {
    fun tribonacci(n: Int): Int {
        if (n == 0) return 0
        if (n <= 2) return 1
        var a = 0
        var b = 1
        var c = 1
        for (i in 3..n) {
            val next = a + b + c
            a = b
            b = c
            c = next
        }
        return c
    }
}
```

**複雜度：** 時間 `O(n)`，額外空間 `O(1)`。

**常見錯誤：** 在算 next 之前就改 a 或 b，造成新舊值混用；把索引 0 當成第 1 項而位移。

**理解自測：** a、b、c 能不能只留下 c？
**答案：** 不行，下一項需要前面三個答案，只有 c 不夠。

## 746. Min Cost Climbing Stairs

**難度：Easy｜觀念：最小成本 DP**
[英文原題](https://leetcode.com/problems/min-cost-climbing-stairs/) · [官方中文](https://leetcode.cn/problems/min-cost-climbing-stairs/)

### 中文題意與輸入輸出

第 i 階離開時要付 `cost[i]`，付完可向上走一或兩階。可以直接從索引 0 或 1 開始；目標是越過最後一階，來到索引 n 的頂端。回傳最少總花費。階數 2–1000，每階費用 0–999。

### 白話思路與手算

不能只看眼前哪一階便宜，因為今天的選擇會改變明天能跳去哪裡。改問「要到第 i 階，最後一步從哪裡來？」只可能來自 i−1 或 i−2。

**狀態：** `dp[i]` 是「到達 i，但還沒付 i 的費用」的最低成本。**初始：** `dp[0]=dp[1]=0`，因為允許直接站上去。**轉移：** `min(dp[i−1]+cost[i−1], dp[i−2]+cost[i−2])`。**方向：** 2 到 n，由低到高；答案是 `dp[n]`，不是 `dp[n−1]`。

原創例 `cost=[5,2,4,1]`：

```text
dp[0]=0, dp[1]=0
dp[2]=min(0+2,0+5)=2
dp[3]=min(2+4,0+2)=2
dp[4]=min(2+1,2+4)=3 → 從1走到3，再到頂端
```

### Kotlin 解答

```kotlin
class Solution {
    fun minCostClimbingStairs(cost: IntArray): Int {
        val n = cost.size
        val dp = IntArray(n + 1)
        for (i in 2..n) {
            dp[i] = minOf(dp[i - 1] + cost[i - 1], dp[i - 2] + cost[i - 2])
        }
        return dp[n]
    }
}
```

**複雜度：** n 是階數；時間 `O(n)`，空間 `O(n)`。理解後可像 1137 一樣只存前兩項，降為 `O(1)`，此處保留表格方便對照。

**常見錯誤：** 把頂端當成最後一個付費階梯；混用「到達的成本」與「已付本階的成本」兩種狀態定義。

**理解自測：** 只有兩階 `[9,3]`，答案是多少？
**答案：** 3。直接從索引 1 開始，付 3 後走到頂端。

## 198. House Robber

**難度：Medium｜觀念：選或不選 DP**
[英文原題](https://leetcode.com/problems/house-robber/) · [官方中文](https://leetcode.cn/problems/house-robber/)

### 中文題意與輸入輸出

一排房屋各有 `nums[i]` 元，不能同時選相鄰兩間，求最多可以取得多少。輸入長度 1–100，每個金額 0–400；房屋排列是一直線，不是環形。

### 白話思路與手算

「每次挑最大間」可能卡住左右兩間，合計反而更少。對前 i 間的最後一間，只有兩種可能：不選它，沿用前 i−1 間最佳值；選它，則前一間不能選，接上前 i−2 間最佳值。

**狀態：** `dp[i]` 是前 i 間能取得的最大金額。**初始：** `dp[0]=0`、`dp[1]=nums[0]`。**轉移：** `max(dp[i−1], dp[i−2]+nums[i−1])`。**方向：** i 遞增。程式用 `previous` 存前一項、`twoBack` 存前兩項，先算 current 再更新。

原創例 `[4,1,2,7]`：

```text
前0間 → 0
前1間 → 4
前2間 → max(4,0+1)=4
前3間 → max(4,4+2)=6
前4間 → max(6,4+7)=11 → 選4和7
```

兩個分支已包含所有合法可能，取最大值不會漏掉最佳選法。

### Kotlin 解答

```kotlin
class Solution {
    fun rob(nums: IntArray): Int {
        var twoBack = 0
        var previous = 0
        for (money in nums) {
            val current = maxOf(previous, twoBack + money)
            twoBack = previous
            previous = current
        }
        return previous
    }
}
```

**複雜度：** n 是房屋數；時間 `O(n)`、額外空間 `O(1)`。

**常見錯誤：** 只算奇數位置和偶數位置兩種選法，但最佳答案不一定隔一間選到底；更新順序使 twoBack 變成今天的答案。

**理解自測：** `[5,1,1,5]` 的答案是 6 嗎？
**答案：** 是 10，第一間和第四間不相鄰，可以一起選。

## 790. Domino and Tromino Tiling

**難度：Medium｜觀念：DP 加上不完整狀態**
[英文原題](https://leetcode.com/problems/domino-and-tromino-tiling/) · [官方中文](https://leetcode.cn/problems/domino-and-tromino-tiling/)

### 中文題意與輸入輸出

用兩格骨牌與三格 L 形拼片鋪滿 2×n 棋盤，拼片可以旋轉，不能重疊或留洞。求鋪法數，答案除以 1,000,000,007 後取餘數。`1<=n<=1000`。

### 白話思路與圖解

只記「完全鋪滿」還不夠：L 形會讓邊界留下缺角，之後再補齊。把半成品也當成一種狀態，才能避免漏算。

```text
F(i)：兩排都完整        G(i)：右上角缺一格的形狀
■ ■ ... ■               ■ ■ ... □
■ ■ ... ■               ■ ■ ... ■
```

`F[i]` 表示 2×i 完整棋盤的鋪法。`G[i]` 表示上述**指定右上缺角**棋盤的鋪法；右下缺角由對稱性有相同數量，但不是同一個圖形。

**初始：** `F[0]=1`：空棋盤什麼都不放也算一種完成方法。`F[1]=1`，`G[0]=G[1]=0`。

**轉移：**

- `F[i]=F[i−1]+F[i−2]+2*G[i−1]`。右邊放一塊直骨牌、放兩塊橫骨牌，或用一塊 L 補好上／下缺角。這三類按最後邊界形狀區分，不會重複。
- `G[i]=G[i−1]+F[i−2]`。從相反方向缺角形狀接一塊橫骨牌，或從較短的完整棋盤接一塊 L。兩種缺角數量相同，所以可只存一種的數量。

**方向：** i 從 2 到 n，兩個公式只看較小索引。

原創例 `n=4`：

```text
i：  0 1 2 3  4
F：  1 1 2 5 11
G：  0 0 1 2  4
F[4]=F[3]+F[2]+2*G[3]=5+2+4=11
```

### Kotlin 解答

```kotlin
class Solution {
    fun numTilings(n: Int): Int {
        val mod = 1_000_000_007L
        val full = LongArray(n + 1)
        val gap = LongArray(n + 1)
        full[0] = 1L
        if (n >= 1) full[1] = 1L
        for (i in 2..n) {
            full[i] = (full[i - 1] + full[i - 2] + 2L * gap[i - 1]) % mod
            gap[i] = (gap[i - 1] + full[i - 2]) % mod
        }
        return full[n].toInt()
    }
}
```

**複雜度：** 時間 `O(n)`，空間 `O(n)`。只保留必要的前項可降到 `O(1)`；先理解狀態比背更短公式重要。

**常見錯誤：** 忘記上下兩種缺角的倍數 2；認為空棋盤有 0 種鋪法，導致所有由空棋盤延伸的情況被吃掉；模數運算前先用 Int 相加而溢位。

**理解自測：** 為什麼 G(2)=1？
**答案：** 2×2 去掉右上角剩三格，恰好是一塊 L，只有一種覆蓋方式。

## 62. Unique Paths

**難度：Medium｜觀念：二維 DP**
[英文原題](https://leetcode.com/problems/unique-paths/) · [官方中文](https://leetcode.cn/problems/unique-paths/)

### 中文題意與輸入輸出

在 m 排、n 欄的格子中，從左上角出發，每次只能向右或向下走一格，求到右下角的路線數。`1<=m,n<=100`；測資保證答案最多 2×10⁹。沒有障礙物。

### 白話思路與手算

列出所有路會指數成長。不要記住每條路長什麼樣，只要記住到每格有幾條。

**狀態：** `dp[r][c]` 是到第 r 排、第 c 欄的方法數。**初始：** 第一排與第一欄都是 1，因為只能一路向右或一路向下。**轉移：** 其他格是「上面的方法數＋左邊的方法數」。**方向：** 由上到下、每排由左到右，確保依賴已算好。

原創例 `m=3,n=3`：

```text
1 1 1
1 2 3
1 3 6 ← 3(上面)+3(左邊)
```

最後一步來自上面與左邊是互斥的兩群路線，兩群加起來恰好是全部，因此可以直接相加。

### Kotlin 解答

```kotlin
class Solution {
    fun uniquePaths(m: Int, n: Int): Int {
        val dp = Array(m) { IntArray(n) { 1 } }
        for (r in 1 until m) {
            for (c in 1 until n) {
                dp[r][c] = dp[r - 1][c] + dp[r][c - 1]
            }
        }
        return dp[m - 1][n - 1]
    }
}
```

**複雜度：** 時間、空間皆 `O(mn)`；之後可只留一排而降空間至 `O(n)`，因為上一排用過就不必保留。

**常見錯誤：** 把格子數和移動步數混淆；第一排全部設 0；忘記 m 或 n 可以是 1。

**理解自測：** 1×5 有幾條路？
**答案：** 1 條，只能一直向右。

## 1143. Longest Common Subsequence

**難度：Medium｜觀念：兩個字串的前綴 DP**
[英文原題](https://leetcode.com/problems/longest-common-subsequence/) · [官方中文](https://leetcode.cn/problems/longest-common-subsequence/)

### 中文題意與輸入輸出

輸入兩個小寫英文字串，找同時出現在兩者中的最長「子序列」長度。子序列可以跳過字元，但不能改變順序，也不需要連續。兩個長度都是 1–1000；沒有共同字元就回傳 0。

### 白話思路與手算

每個字元都猜要留或刪會爆炸。我們改記「兩個字串各看到某個位置時，最佳答案是多少」。

**狀態：** `dp[i][j]` 是 text1 前 i 個字元與 text2 前 j 個字元的 LCS 長度。注意 i 是**數量**，目前字元是 `text1[i−1]`。**初始：** 任一字串長度為 0，答案為 0。**轉移：** 最後字元相同，接上這一對，`dp[i−1][j−1]+1`；不同，最後兩個字元不能互相配對，至少略過一邊，取 `max(dp[i−1][j],dp[i][j−1])`。**方向：** i、j 都由小到大。

原創例 `text1="abca",text2="aca"`：

```text
      空 a c a
空     0 0 0 0
a      0 1 1 1
b      0 1 1 1
c      0 1 2 2
a      0 1 2 3 → 共同子序列aca，長度3
```

### Kotlin 解答

```kotlin
class Solution {
    fun longestCommonSubsequence(text1: String, text2: String): Int {
        val m = text1.length
        val n = text2.length
        val dp = Array(m + 1) { IntArray(n + 1) }
        for (i in 1..m) {
            for (j in 1..n) {
                dp[i][j] = if (text1[i - 1] == text2[j - 1]) {
                    dp[i - 1][j - 1] + 1
                } else {
                    maxOf(dp[i - 1][j], dp[i][j - 1])
                }
            }
        }
        return dp[m][n]
    }
}
```

**複雜度：** m、n 是兩字串長度；時間、空間都是 `O(mn)`。空間可壓成一排，但需要保存左上角舊值，初學先用完整表。

**常見錯誤：** 誤解成必須連續的 substring；字元不同就把格子歸零，那是在解另一道問題。

**理解自測：** `"abc"` 與 `"cba"` 的答案為什麼不是 3？
**答案：** 共同字元雖有三種，但順序相反，最多只能選一個，答案是 1。

## 714. Best Time to Buy and Sell Stock with Transaction Fee

**難度：Medium｜觀念：持有／空手狀態 DP**
[英文原題](https://leetcode.com/problems/best-time-to-buy-and-sell-stock-with-transaction-fee/) · [官方中文](https://leetcode.cn/problems/best-time-to-buy-and-sell-stock-with-transaction-fee/)

### 中文題意與輸入輸出

每天股價放在 prices，可做多次買賣，但最多同時持有一股；每完成一買一賣支付一次 fee。回傳最大獲利，可以完全不交易。天數 1–50,000，價格為 1–49,999，fee 為 0–49,999。

### 白話思路與手算

看到上漲就賣可能付太多次手續費。記錄每天結束時兩種狀態的最好成績，而非立刻決定某筆交易一定要做。

**狀態：** `cash` 是今天結束空手的最大淨收入；`hold` 是今天結束持有一股的最大淨收入（買入支出已扣除，尚未把股票賣掉，所以可以是負數）。**初始：** 第一天 `cash=0`、`hold=-prices[0]`。**轉移：** 新 cash 是昨天空手不動或昨天持有今天賣出，`max(oldCash,oldHold+price-fee)`；新 hold 是昨天持有不動或昨天空手今天買入，`max(oldHold,oldCash-price)`。**方向：** 依日期向後。最終回傳空手 cash。

原創例 `prices=[2,6,3,8],fee=2`：

```text
價格： 2  6  3  8
cash： 0  2  2  5
hold：-2 -2 -1 -1
2買6賣賺2；3買8賣賺3；總共5
```

### Kotlin 解答

```kotlin
class Solution {
    fun maxProfit(prices: IntArray, fee: Int): Int {
        var cash = 0
        var hold = -prices[0]
        for (i in 1 until prices.size) {
            val oldCash = cash
            val oldHold = hold
            cash = maxOf(oldCash, oldHold + prices[i] - fee)
            hold = maxOf(oldHold, oldCash - prices[i])
        }
        return cash
    }
}
```

**複雜度：** n 是天數；時間 `O(n)`，空間 `O(1)`。

**常見錯誤：** 買入與賣出都扣 fee，等於扣兩次；最後回傳 hold，那只是帶著庫存的帳面狀態。

**理解自測：** 價格 `[3,4]`、fee=2 時應該交易嗎？
**答案：** 不交易，獲利 0 比交易後的 -1 好。

## 72. Edit Distance

**難度：Medium｜觀念：編輯操作 DP**
[英文原題](https://leetcode.com/problems/edit-distance/) · [官方中文](https://leetcode.cn/problems/edit-distance/)

### 中文題意與輸入輸出

把 word1 變成 word2，每次可插入、刪除或替換一個字元，求最少操作次數。字串是小寫英文，長度各為 0–500，可以是空字串。

### 白話思路與手算

一口氣考慮整個字串很難，先問較短的前綴要幾次操作。

**狀態：** `dp[i][j]` 表示 word1 前 i 個字元，轉成 word2 前 j 個字元的最少次數。**初始：** `dp[i][0]=i`（全刪）、`dp[0][j]=j`（全插）。**轉移：** 尾字元相同就不用多做，沿用左上 `dp[i−1][j−1]`；不同則以下三者取最小再加 1：上方 `dp[i−1][j]` 對應刪掉來源最後一字；左方 `dp[i][j−1]` 對應補上目標最後一字；左上 `dp[i−1][j−1]` 對應替換。**方向：** 左上到右下，依賴先算完。

原創例 `word1="cat",word2="cut"`：

```text
       空 c u t
空      0 1 2 3
c       1 0 1 2
a       2 1 1 2
t       3 2 2 1
```

最後一格是 1：把 a 改成 u。看格子 `[2][2]`：`"ca"→"cu"` 只要替換，因此由左上 0 加 1 得到。

### Kotlin 解答

```kotlin
class Solution {
    fun minDistance(word1: String, word2: String): Int {
        val m = word1.length
        val n = word2.length
        val dp = Array(m + 1) { IntArray(n + 1) }
        for (i in 0..m) dp[i][0] = i
        for (j in 0..n) dp[0][j] = j
        for (i in 1..m) {
            for (j in 1..n) {
                dp[i][j] = if (word1[i - 1] == word2[j - 1]) {
                    dp[i - 1][j - 1]
                } else {
                    1 + minOf(dp[i - 1][j], dp[i][j - 1], dp[i - 1][j - 1])
                }
            }
        }
        return dp[m][n]
    }
}
```

**複雜度：** m、n 是字串長度；時間 `O(mn)`，空間 `O((m+1)(n+1))`，非空情況慣寫 `O(mn)`。

**常見錯誤：** 第一排和第一欄全部留 0；把兩字元交換算一步，題目並沒有交換操作；把索引與前綴長度混淆。

**理解自測：** `""` 變成 `"go"` 需要幾次？
**答案：** 2 次，分別插入 g 和 o。

## 338. Counting Bits

**難度：Easy｜觀念：位元、DP**
[英文原題](https://leetcode.com/problems/counting-bits/) · [官方中文](https://leetcode.cn/problems/counting-bits/)

### 中文題意與輸入輸出

輸入 n，輸出長度 n+1 的陣列；第 i 格放 i 的二進位有幾個 1。`0<=n<=100000`。本解不用內建計算 1 位元數的函式，並達到線性時間。

### 白話思路與手算

把數字右移一位，就像把二進位最右邊的字拿掉。拿掉的字若是 1，再加回一個就好。Kotlin 的 `shr` 是右移，`and 1` 用來看最右一位。

**狀態：** `answer[i]` 是 i 的 1 位元數。**初始：** `answer[0]=0`。**轉移：** `answer[i]=answer[i shr 1]+(i and 1)`。**方向：** 1 到 n，因為 i/2 一定比 i 小，已經算完。

原創例 `n=4`：

```text
0=000 → 0
1=001 → answer[0]+1=1
2=010 → answer[1]+0=1
3=011 → answer[1]+1=2
4=100 → answer[2]+0=1
輸出 [0,1,1,2,1]
```

### Kotlin 解答

```kotlin
class Solution {
    fun countBits(n: Int): IntArray {
        val answer = IntArray(n + 1)
        for (i in 1..n) {
            answer[i] = answer[i shr 1] + (i and 1)
        }
        return answer
    }
}
```

**複雜度：** 時間 `O(n)`，輸出空間 `O(n)`，除此之外額外空間 `O(1)`。

**常見錯誤：** 配置 n 格而非 n+1；把位元 `and` 和布林 `&&` 混淆。

**理解自測：** 10 的二進位是 1010，不重新數全部位元，如何算？
**答案：** `answer[5]+0`；5 是 101，有兩個 1，所以答案 2。

## 136. Single Number

**難度：Easy｜觀念：XOR 抵消**
[英文原題](https://leetcode.com/problems/single-number/) · [官方中文](https://leetcode.cn/problems/single-number/)

### 中文題意與輸入輸出

非空整數陣列中，只有一個值出現一次，其他值恰好各出現兩次。找出單獨的值。長度最多 30,000，值介於 -30,000 到 30,000。要求線性時間、常數額外空間。

### 白話思路與手算

用 Map 數次數很直覺，但需要額外空間。`xor` 是逐位「不同才得到 1」：同一個值 XOR 自己得到 0；任何值 XOR 0 等於自己；順序可以調換。所以把所有值 XOR 在一起，成雙的就消掉，剩下單獨那個。

原創例 `[7,3,7]`：

```text
  111 (7)
xor011 (3)
= 100 (4)
xor111 (7)
= 011 (3) → 答案3
```

中途的 4 不需要有題目意義，它只是還沒抵消完的位元狀態。負數也能用，因為相同的固定寬度位元一樣會抵消。

### Kotlin 解答

```kotlin
class Solution {
    fun singleNumber(nums: IntArray): Int {
        var answer = 0
        for (num in nums) answer = answer xor num
        return answer
    }
}
```

**複雜度：** n 是元素數；時間 `O(n)`，額外空間 `O(1)`。

**常見錯誤：** 在「其他值出現三次」的變形題直接照抄；把 XOR 寫成 OR，OR 沒有成對抵消的性質。

**理解自測：** 如果陣列只有 `[-8]` 能用嗎？
**答案：** 可以，0 XOR -8 就是 -8。

## 1318. Minimum Flips to Make a OR b Equal to c

**難度：Medium｜觀念：逐位討論**
[英文原題](https://leetcode.com/problems/minimum-flips-to-make-a-or-b-equal-to-c/) · [官方中文](https://leetcode.cn/problems/minimum-flips-to-make-a-or-b-equal-to-c/)

### 中文題意與輸入輸出

輸入正整數 a、b、c，每次可以把 a 或 b 的某一個二進位位元由 0 改 1 或由 1 改 0。c 不能修改。求最少幾次能讓 `(a OR b)==c`。三個數最多 10⁹。

### 白話思路與手算

OR 是「兩邊至少有一個 1，就得到 1」。每個位元互不影響，不像加法會進位，因此每一位各自取最少操作，再相加即可。

```text
目標位元0：a和b都必須0 → 現有幾個1，就翻幾次
目標位元1：a或b至少一個1 → 兩邊都0才需要翻1次
```

原創例 `a=3(011),b=5(101),c=6(110)`：最右位目標 0，但 a、b 都為 1，要翻兩次；其他兩位都已符合，答案 2。這說明「OR 結果和 c 有幾個不同位元」不等於操作次數。

### Kotlin 解答

```kotlin
class Solution {
    fun minFlips(a: Int, b: Int, c: Int): Int {
        var flips = 0
        for (bit in 0 until 31) {
            val x = (a ushr bit) and 1
            val y = (b ushr bit) and 1
            val target = (c ushr bit) and 1
            if (target == 0) flips += x + y
            else if (x == 0 && y == 0) flips++
        }
        return flips
    }
}
```

`ushr` 是右移時左邊補 0；配上 `and 1` 抽出指定的一位。正 Int 只需檢查位元 0–30；題目最大值甚至用不到最高那些位元。

**複雜度：** 固定 31 位，時間與空間皆 `O(1)`；若以可變位寬 B 泛化，時間是 `O(B)`。

**常見錯誤：** 目標為 0、來源兩個都是 1 時只加一次；試圖修改 c。

**理解自測：** 某位 a=0、b=1、目標=1，要翻嗎？
**答案：** 不用，OR 已經是 1。

## 208. Implement Trie (Prefix Tree)

**難度：Medium｜觀念：前綴樹**
[英文原題](https://leetcode.com/problems/implement-trie-prefix-tree/) · [官方中文](https://leetcode.cn/problems/implement-trie-prefix-tree/)

### 中文題意與輸入輸出

實作 `Trie()`、`insert(word)`、`search(word)`、`startsWith(prefix)`。insert 加入單字；search 判斷完整單字是否曾加入；startsWith 判斷是否有單字以指定字首開頭。只有小寫英文，字串長度 1–2000，總操作次數最多 30,000。

### 白話思路與圖解

用 HashSet 存完整字串可以快速查單字，但查共同字首不方便。Trie 像共用資料夾路徑：共同字首只存一份，每個字母是一條路。每個節點有 26 個可能的下一站，`ch-'a'` 決定走哪條。

原創例，先插入 `"car"`、`"cat"`：

```text
root → c → a ┬→ r (end=true)
             └→ t (end=true)
search("ca") = false     // 路走得到，但不是完整單字
startsWith("ca") = true  // 路走得到即可
search("car") = true
```

`end` 像資料夾上寫著「這裡也是一個完整答案」。不能只看有沒有走到節點，否則會把所有字首都當作已插入單字。

### Kotlin 解答

```kotlin
class Trie() {
    private class Node {
        val children = arrayOfNulls<Node>(26)
        var end = false
    }
    private val root = Node()

    fun insert(word: String) {
        var node = root
        for (ch in word) {
            val index = ch - 'a'
            if (node.children[index] == null) node.children[index] = Node()
            node = node.children[index]!!
        }
        node.end = true
    }

    private fun walk(text: String): Node? {
        var node = root
        for (ch in text) {
            node = node.children[ch - 'a'] ?: return null
        }
        return node
    }

    fun search(word: String): Boolean = walk(word)?.end == true

    fun startsWith(prefix: String): Boolean = walk(prefix) != null
}
```

`arrayOfNulls<Node>(26)` 一開始 26 條路都不存在；需要時才建立節點。`?: return null` 表示某一步沒路就立刻查詢失敗。

**複雜度：** 每次操作時間 `O(L)`，L 是這次字串長度。若所有插入字元總數為 S，節點數最多 S+1，空間 `O(26S)=O(S)`；共享前綴能減少實際節點。

**常見錯誤：** 不記 end；每次 insert 都重新建立 root，洗掉舊資料；把英文大小寫混用而索引越界，本題限定小寫。

**理解自測：** 插入 car 後再插入 ca，會破壞 car 嗎？
**答案：** 不會，只把 a 節點的 end 設為 true，r 的路和 end 都保留。

## 1268. Search Suggestions System

**難度：Medium｜觀念：排序與二分；可與 Trie 比較**
[英文原題](https://leetcode.com/problems/search-suggestions-system/) · [官方中文](https://leetcode.cn/problems/search-suggestions-system/)

### 中文題意與輸入輸出

每輸入 searchWord 的一個字元，就從 products 選出以目前字首開頭、字典序最小的最多三個商品。回傳每一步的推薦清單。商品名不重複且都是小寫英文；商品數最多 1000，每個長度最多 3000，總字元數最多 20,000；搜尋字串最多 1000 字元。

### 白話思路與手算

可以用上一題的 Trie，這裡示範另一種較短的方法：先排序，再為每個字首找「第一個字典序不小於字首的位置」。所有同字首商品在排序後會聚在一起，從這裡往後最多檢查三個即可。

原創例 `products=["desk","dog","door","cat"],searchWord="do"`：

```text
排序：[cat,desk,dog,door]
字首d → 第一個>=d是desk → [desk,dog,door]
字首do→ 第一個>=do是dog → [dog,door]
```

下界位置不一定真的有該字首，例如搜尋 `dz`，排序比較找到的位置可能已經越過全部商品。所以還必須用 `startsWith` 確認。遇到第一個不符合就能停：符合的那一整段已經結束了。

### Kotlin 解答

```kotlin
class Solution {
    fun suggestedProducts(products: Array<String>, searchWord: String): List<List<String>> {
        val sorted = products.sortedArray()
        val result = mutableListOf<List<String>>()
        for (length in 1..searchWord.length) {
            val prefix = searchWord.substring(0, length)
            var left = 0
            var right = sorted.size
            while (left < right) {
                val mid = left + (right - left) / 2
                if (sorted[mid].compareTo(prefix) < 0) left = mid + 1
                else right = mid
            }
            val suggestions = mutableListOf<String>()
            var index = left
            while (index < sorted.size && suggestions.size < 3) {
                if (!sorted[index].startsWith(prefix)) break
                suggestions.add(sorted[index])
                index++
            }
            result.add(suggestions)
        }
        return result
    }
}
```

**複雜度：** P 是商品數、L 是最長商品長度、Q 是搜尋字串長度。排序最壞 `O(P log P·L)`；字串比較不是 O(1)，逐步搜尋的保守上界是 `O(Q² log(P+1))`，包含各長度字首比較與建立。額外空間 `O(P+Q)`，另有 `O(Q)` 個輸出清單及最多 3Q 個商品引用（未複製整個商品字串）。

**常見錯誤：** 沒排序就拿前三個；只找得到三個時才加入結果，導致輸出長度不對；把字串比較一律當作常數時間。

**理解自測：** 第一個字首就沒有商品，後面還要放結果嗎？
**答案：** 要，每個輸入字元都對應一個清單，後面每步都是空清單。

## 435. Non-overlapping Intervals

**難度：Medium｜觀念：貪心、最早結束**
[英文原題](https://leetcode.com/problems/non-overlapping-intervals/) · [官方中文](https://leetcode.cn/problems/non-overlapping-intervals/)

### 中文題意與輸入輸出

輸入多個 `[start,end]`，移除最少幾個才能使剩下的區間互不重疊？端點接觸不算重疊，例如一個剛好結束時另一個開始可以保留。區間數 1–100,000，端點在 -50,000 到 50,000，start 嚴格小於 end。

### 白話思路與手算

「刪最少」等同「留最多」。先按結束時間排序，能選時就選最早結束的，替後面留下最多空間。

為何安全？假設某個最佳安排的第一段比我們選的結束更晚，把它換成最早結束的這段，後面原本能接上的區間仍能接上，數量不會變少。對後面重複同樣道理即可。

原創例 `[[1,4],[2,3],[3,5],[6,8]]`：

```text
按end排序：[2,3] [1,4] [3,5] [6,8]
留[2,3] → [1,4]起點1<3，刪掉
留[3,5] → 端點3接觸可以
留[6,8] → 共留3段，刪1段
```

### Kotlin 解答

```kotlin
class Solution {
    fun eraseOverlapIntervals(intervals: Array<IntArray>): Int {
        val sorted = intervals.sortedBy { it[1] }
        var end = Int.MIN_VALUE
        var kept = 0
        for (interval in sorted) {
            if (interval[0] >= end) {
                kept++
                end = interval[1]
            }
        }
        return intervals.size - kept
    }
}
```

**複雜度：** n 是區間數；時間 `O(n log n)`，額外空間 `O(n)`，本程式使用排序副本以保留輸入。

**常見錯誤：** 先挑最早開始，可能被一個超長區間佔住；接觸端點時用 `>`，錯刪本來可共存的區間。

**理解自測：** `[1,10]` 與 `[2,3]` 只能留一個，優先留哪個？
**答案：** `[2,3]`，它較早結束，後面選擇只會更多。

## 452. Minimum Number of Arrows to Burst Balloons

**難度：Medium｜觀念：貪心、區間共同交點**
[英文原題](https://leetcode.com/problems/minimum-number-of-arrows-to-burst-balloons/) · [官方中文](https://leetcode.cn/problems/minimum-number-of-arrows-to-burst-balloons/)

### 中文題意與輸入輸出

每個氣球在水平軸上占 `[start,end]`，從某個 x 往上射箭，就能射破所有包含 x 的氣球。端點也能命中。求射破全部氣球所需的最少箭數。氣球數 1–100,000，端點可能達到 Int 最小值或最大值，start<end。

### 白話思路與手算

挑最早結束的氣球，它一定要被某支箭命中。把這支箭放在它的右端點，能盡可能往右同時照顧其他氣球。已按右端點排序，剩下氣球的右端點都不會比較小；對一支原本命中最早氣球的箭，向右移到該右端點，不會失去它原本命中的剩餘氣球。

原創例 `[[1,5],[2,4],[4,7],[8,9]]`：

```text
先處理[2,4]，在x=4射箭
[1,5]、[2,4]、[4,7]都包含4，一箭破三顆
[8,9]不包含4，再在9射箭 → 共2支
```

與上一題差別：上一題希望區間彼此分開；本題希望一支箭利用重疊。端點相等時**不需要新箭**。

### Kotlin 解答

```kotlin
class Solution {
    fun findMinArrowShots(points: Array<IntArray>): Int {
        val sorted = points.sortedBy { it[1] }
        var arrows = 1
        var position = sorted[0][1]
        for (i in 1 until sorted.size) {
            if (sorted[i][0] > position) {
                arrows++
                position = sorted[i][1]
            }
        }
        return arrows
    }
}
```

**複雜度：** n 是氣球數；時間 `O(n log n)`，額外空間 `O(n)`，包含排序副本。

**常見錯誤：** 比較器寫成 `a[1]-b[1]` 可能溢位，使排序顛倒；判斷新箭用 `>=` 而錯過端點可共同命中的情況。

**理解自測：** `[1,2]`、`[2,8]` 需要幾支箭？
**答案：** 1 支，射在 2。

## 739. Daily Temperatures

**難度：Medium｜觀念：單調堆疊、下一個更大值**
[英文原題](https://leetcode.com/problems/daily-temperatures/) · [官方中文](https://leetcode.cn/problems/daily-temperatures/)

### 中文題意與輸入輸出

輸入每天溫度，回傳每一天要再等幾天才會遇到**嚴格更熱**的一天，之後沒有更熱就填 0。天數 1–100,000，溫度 30–100。

### 白話思路與手算

每一天都往後找，最壞 O(n²)。換個角度：把還沒遇到更熱天氣的日期放進堆疊。新的一天到來，如果比頂端那天熱，那天終於等到了，答案就是今天索引減那天索引。

原創例 `[60,55,55,65]`：

```text
第0天60 → 等待[0]
第1天55 → 等待[0,1]
第2天55 → 一樣熱不算 → 等待[0,1,2]
第3天65 → 解決2，等1天；解決1，等2天；解決0，等3天
輸出[3,2,1,0]
```

堆疊裡對應的溫度由底到頂不增加。頂端較冷，解決後可以繼續往下看；頂端都不比今天冷，下面更熱的更不可能被今天解決。每個等待者被移除那天，就是它第一次遇到更熱天，因為若之前有更熱天，它早已被移除了。

### Kotlin 解答

```kotlin
import java.util.ArrayDeque

class Solution {
    fun dailyTemperatures(temperatures: IntArray): IntArray {
        val answer = IntArray(temperatures.size)
        val waiting = ArrayDeque<Int>() // 存日期索引，不是溫度
        for (today in temperatures.indices) {
            while (waiting.isNotEmpty() && temperatures[today] > temperatures[waiting.peekLast()]) {
                val earlier = waiting.removeLast()
                answer[earlier] = today - earlier
            }
            waiting.addLast(today)
        }
        return answer
    }
}
```

**複雜度：** n 是天數；總時間 `O(n)`，因為每個索引最多加入、移除一次，不是看見 while 包在 for 裡就必定 O(n²)。堆疊額外空間 `O(n)`，輸出也 `O(n)`。

**常見錯誤：** 存溫度而忘記日期，無法算距離；使用 `>=` 把相同溫度也當成更熱；最後還等不到的日期不用改，IntArray 預設 0 即是答案。

**理解自測：** `[70,70]` 的第一個答案是多少？
**答案：** 0，第二天沒有嚴格比較熱。

## 901. Online Stock Span

**難度：Medium｜觀念：單調堆疊、合併區段**
[英文原題](https://leetcode.com/problems/online-stock-span/) · [官方中文](https://leetcode.cn/problems/online-stock-span/)

### 中文題意與輸入輸出

實作 `StockSpanner()` 與 `next(price)`。每次收到今天股價，要回傳從今天往回連續幾天的股價都**小於等於今天**，包含今天自己。不能跳過中間較高的日子。價格 1–100,000，next 最多呼叫 10,000 次。

### 白話思路與手算

每天往回逐日掃描，最壞 O(n²)。把一段已經被某個價格統合的日子壓成 `(price,span)`。新價格能蓋過頂端的價格，就能連它代表的整段一起吃進來，不必一日一日重新算。

原創例依序呼叫價格 `[40,30,35,35,50]`：

```text
40 → [(40,1)]                    回傳1
30 → [(40,1),(30,1)]             回傳1
35 → 合併30 → [(40,1),(35,2)]     回傳2
35 → 合併35 → [(40,1),(35,3)]     回傳3
50 → 合併35那3天與40那1天，再加今天 → 回傳5
```

每段的 price 是那一段的最大值。如果今天連這個最大值都大於等於，就保證整段每一天都符合。遇到第一個更高價格必須停止，因為題目要求連續。

### Kotlin 解答

```kotlin
import java.util.ArrayDeque

class StockSpanner() {
    private data class Entry(val price: Int, val span: Int)
    private val stack = ArrayDeque<Entry>()

    fun next(price: Int): Int {
        var span = 1 // 今天自己
        while (stack.isNotEmpty() && stack.peekLast().price <= price) {
            span += stack.removeLast().span
        }
        stack.addLast(Entry(price, span))
        return span
    }
}
```

**複雜度：** 累計 n 次 next 的總時間 `O(n)`，平均攤到每次是 `O(1)`，稱為「攤銷」。某一次仍可能移除全部堆疊而花 `O(n)`。最大額外空間 `O(n)`。

**常見錯誤：** 移除一段只加 1，而忘記它可能代表多天；把堆疊寫在 next 裡，每天都重新清空；使用 `<` 漏掉相同價格也能合併。

**理解自測：** 股價 `[90,20,30]`，最後一次為什麼不是 3？
**答案：** 90 比 30 高，是不能跨越的界線，所以只含今天 30 與昨天 20，答案是 2。
