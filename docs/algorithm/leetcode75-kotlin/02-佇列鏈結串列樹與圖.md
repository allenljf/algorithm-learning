先建立四個畫面：**鏈結串列**像尋寶紙條，每張只有數字與下一張的位置；**二元樹**像限制每層資料夾最多有左右兩個子資料夾的結構；**圖**像交通網，可能繞圈，因此要記錄去過哪裡；**Heap**像自動把最便宜商品放到取貨口的箱子，它只保證箱口最小，不保證裡面全部排好。

本冊使用 `java.util.ArrayDeque`：`addLast` 從尾端放入、`removeFirst` 從前端拿出，是先來先服務的佇列；改成 `removeLast` 就是後放先拿的堆疊。DFS 是先沿一條路往下探索，BFS 是先探索所有一步可達的位置，再探索兩步的位置。遇到非常深的樹，本冊優先使用明確的堆疊或佇列，避免 JVM 遞迴呼叫過深。

`ListNode` 的 `next` 與 `TreeNode` 的 `left/right` 由 LeetCode 提供，節點值寫成 ``node.`val` ``，因為 `val` 是 Kotlin 關鍵字。這些節點是物件參照，修改 `next` 是改箭頭，不是複製整串資料。各題程式獨立貼到平台，不能把多個 `class Solution` 同時貼在一起。

## 649. Dota2 Senate

**難度：Medium** · [英文原題](https://leetcode.com/problems/dota2-senate/) · [官方中文](https://leetcode.cn/problems/dota2-senate/)

### 中文題意（自行改寫，非逐字翻譯）

字串只有 R 與 D，長度 1–10,000。議員依座位循環發言，每人可以永久禁掉一位對手；假設都採有利自己陣營的策略，回傳 `Radiant` 或 `Dire`。

### 白話思路與手算

直覺是每輪重掃整條字串，但已被禁的人讓流程難管理。我們只記錄「還能發言的人，下次什麼時候發言」。用兩個佇列分別存 R、D 的時間。較早的人先動手，禁掉最早即將行動的對手；留下較晚的對手不會讓自己更安全，所以這樣選合理。贏得這次對決的人加上字串長度，排到下一輪。

原創例子 `DRRD`：D 時間 `[0,3]`、R 時間 `[1,2]`。0 禁 1，D 回到時間 4；2 禁 3，R 回到 6；4 禁 6，R 沒人，答案 `Dire`。每次對決永久少一人，不會無限循環。

```kotlin
import java.util.ArrayDeque
class Solution {
    fun predictPartyVictory(senate: String): String {
        val r = ArrayDeque<Int>()
        val d = ArrayDeque<Int>()
        for (i in senate.indices) {
            if (senate[i] == 'R') r.addLast(i) else d.addLast(i)
        }
        while (r.isNotEmpty() && d.isNotEmpty()) {
            val ri = r.removeFirst()
            val di = d.removeFirst()
            if (ri < di) r.addLast(ri + senate.length)
            else d.addLast(di + senate.length)
        }
        return if (r.isNotEmpty()) "Radiant" else "Dire"
    }
}
```

**複雜度：** n 為議員數，時間 O(n)，空間 O(n)。**常見錯誤：** 直接比較兩黨人數，忽略出手順序。**自測：** 為何勝者不是直接放回原座位數？**答案：** 他本輪已經出手，必須排到下一輪。

## 2095. Delete the Middle Node of a Linked List

**難度：Medium** · [英文原題](https://leetcode.com/problems/delete-the-middle-node-of-a-linked-list/) · [官方中文](https://leetcode.cn/problems/delete-the-middle-node-of-a-linked-list/)

### 中文題意（自行改寫，非逐字翻譯）

輸入 1–100,000 個節點的串列，刪掉從 0 開始數第 `n / 2` 個，回傳新開頭。偶數長度刪兩個中間位置的後者。值為 1–100,000。

### 白話思路與手算

先數長度再走一次可以做；快慢指標則一趟完成。慢指標一次走一格，快指標一次走兩格，快指標到終點時，慢指標剛好走了一半。另存慢指標前一格，才能接回箭頭。

原創例子 `8 → 6 → 4 → 2 → null`：慢走到 6 時快到 4；慢到 4 時快離開串列，因此把 6 的 next 改成 2，得到 `8 → 6 → 2`。不是把 4 的值設為 0。

```kotlin
class Solution {
    fun deleteMiddle(head: ListNode?): ListNode? {
        if (head?.next == null) return null
        var slow = head
        var fast = head
        var previous: ListNode? = null
        while (fast != null && fast.next != null) {
            previous = slow
            slow = slow?.next
            fast = fast.next?.next
        }
        previous?.next = slow?.next
        return head
    }
}
```

**複雜度：** n 為節點數，時間 O(n)，額外空間 O(1)。會修改輸入串列。**常見錯誤：** 一個節點刪除後仍回傳 head。**自測：** 6 個節點刪哪個索引？**答案：** 索引 3，也就是第 4 個。

## 328. Odd Even Linked List

**難度：Medium** · [英文原題](https://leetcode.com/problems/odd-even-linked-list/) · [官方中文](https://leetcode.cn/problems/odd-even-linked-list/)

### 中文題意（自行改寫，非逐字翻譯）

把第 1、3、5…個節點放前面，第 2、4、6…個放後面，各組內順序不變。最多 10,000 個節點，可為空；值在 ±1,000,000。要求 O(n) 時間、O(1) 額外空間。

### 白話思路與手算

另建兩個陣列容易，但不符空間要求。改成兩條接龍：odd 追蹤奇數組最後一個，even 追蹤偶數組最後一個。先記住偶數組開頭，最後把兩組接起來。

原創例子 `9 → 8 → 7 → 6`，抽出的兩條是 `9 → 7` 與 `8 → 6`，接成 `9 → 7 → 8 → 6`。每次跨過一個節點，所以每組仍保留原來先後順序。判斷的是位置，不是數字奇偶。

```kotlin
class Solution {
    fun oddEvenList(head: ListNode?): ListNode? {
        if (head == null) return null
        var odd: ListNode = head
        var even: ListNode? = head.next
        val evenHead = even
        while (even?.next != null) {
            odd.next = even.next
            odd = odd.next!!
            even.next = odd.next
            even = even.next
        }
        odd.next = evenHead
        return head
    }
}
```

**複雜度：** n 為節點數，時間 O(n)，額外空間 O(1)，修改輸入箭頭。**常見錯誤：** 忘記保存 evenHead，最後找不到偶數組開頭。**自測：** `[2,4,6]` 結果？**答案：** `[2,6,4]`。

## 206. Reverse Linked List

**難度：Easy** · [英文原題](https://leetcode.com/problems/reverse-linked-list/) · [官方中文](https://leetcode.cn/problems/reverse-linked-list/)

### 中文題意（自行改寫，非逐字翻譯）

輸入一條可能為空的串列，把順序反轉並回傳新開頭。節點最多 5,000，值在 ±5,000。

### 白話思路與手算

把數字放陣列再倒著建節點可以，但會多用記憶體。只改箭頭就好：previous 是已經反轉完成的開頭，current 是尚未處理的位置。先保存下一張紙條位置，再把箭頭轉回去，否則會找不到後半串。

原創例子：

```text
原本：null    7 → 3 → 9 → null
第一步：null ← 7    3 → 9 → null
第二步：null ← 7 ← 3    9 → null
完成：null ← 7 ← 3 ← 9（新 head 是 9）
```

```kotlin
class Solution {
    fun reverseList(head: ListNode?): ListNode? {
        var previous: ListNode? = null
        var current = head
        while (current != null) {
            val next = current.next // 改箭頭前，先保存剩下的路
            current.next = previous
            previous = current
            current = next
        }
        return previous
    }
}
```

**複雜度：** n 為節點數，時間 O(n)，額外空間 O(1)，修改輸入串列。**常見錯誤：** 改完 current.next 才讀 next。**自測：** 為何 previous 初始是 null？**答案：** 原本第一個節點最後會變尾巴，尾巴必須指向 null。

## 2130. Maximum Twin Sum of a Linked List

**難度：Medium** · [英文原題](https://leetcode.com/problems/maximum-twin-sum-of-a-linked-list/) · [官方中文](https://leetcode.cn/problems/maximum-twin-sum-of-a-linked-list/)

### 中文題意（自行改寫，非逐字翻譯）

串列長度一定為偶數，2–100,000 個節點，值為 1–100,000。第一個配最後一個、第二個配倒數第二個，回傳最大的兩數和。

### 白話思路與手算

先放陣列，用 `i` 與 `n-1-i` 配對最容易理解。本題練習前兩題組合：快慢指標找後半段，把後半段反轉；這樣從兩個開頭同步往前就能配對，不需要陣列。

原創例子 `2 → 9 → 3 → 8`，後半 `3 → 8` 反轉為 `8 → 3`；比較 `2+8=10`、`9+3=12`，答案 12。每一步左右恰好向中央縮一格。

```kotlin
class Solution {
    fun pairSum(head: ListNode?): Int {
        var slow = head
        var fast = head
        while (fast?.next != null) {
            slow = slow?.next
            fast = fast.next?.next
        }
        var reversed: ListNode? = null
        while (slow != null) {
            val next = slow.next
            slow.next = reversed
            reversed = slow
            slow = next
        }
        var left = head
        var right = reversed
        var best = 0
        while (right != null) {
            best = maxOf(best, left!!.`val` + right.`val`)
            left = left.next
            right = right.next
        }
        return best
    }
}
```

**複雜度：** n 為節點數，時間 O(n)，額外空間 O(1)。此版修改後半箭頭，沒有還原；若呼叫者需要原串列，應再反轉後半還原。**常見錯誤：** 同時走完整個左串列，超出配對次數。**自測：** 需要比幾組？**答案：** n/2 組，以反轉後的右半走完為停止條件。

## 104. Maximum Depth of Binary Tree

**難度：Easy** · [英文原題](https://leetcode.com/problems/maximum-depth-of-binary-tree/) · [官方中文](https://leetcode.cn/problems/maximum-depth-of-binary-tree/)

### 中文題意（自行改寫，非逐字翻譯）

求樹最深有幾層，根算第 1 層；空樹為 0。最多 10,000 個節點，值在 ±100。

### 白話思路與手算

可以問左右子樹各多深，再加 1，這就是遞迴。不過樹若像長鏈，Kotlin 呼叫可能太深。本版用 BFS：先把根排隊，整批處理完一層再加一。必須先記住本層人數，新加入的孩子留到下一輪。

原創樹：`4` 左孩 `2`，`2` 左孩 `1`，沒有其他節點。佇列每層依序 `[4] → [2] → [1] → []`，答案 3。每輪只放下一層，所以輪數等於深度。

```kotlin
import java.util.ArrayDeque
class Solution {
    fun maxDepth(root: TreeNode?): Int {
        if (root == null) return 0
        val queue = ArrayDeque<TreeNode>()
        queue.addLast(root)
        var depth = 0
        while (queue.isNotEmpty()) {
            val count = queue.size
            repeat(count) {
                val node = queue.removeFirst()
                node.left?.let { queue.addLast(it) }
                node.right?.let { queue.addLast(it) }
            }
            depth++
        }
        return depth
    }
}
```

**複雜度：** n 為節點數、w 為最大層寬，時間 O(n)，空間 O(w)，最壞 O(n)。**常見錯誤：** 把深度當邊數，單節點回傳 0。**自測：** 只有根節點多深？**答案：** 1。

## 872. Leaf-Similar Trees

**難度：Easy** · [英文原題](https://leetcode.com/problems/leaf-similar-trees/) · [官方中文](https://leetcode.cn/problems/leaf-similar-trees/)

### 中文題意（自行改寫，非逐字翻譯）

兩棵樹各有 1–200 個節點，值為 0–200。各自把葉子從左到右讀出來，序列完全相同就回傳 true。葉子是左右孩子都沒有的節點。

### 白話思路與手算

不需要比較整棵樹的形狀。深度優先走訪，看到葉子才收集值。堆疊是後放先取，所以先放右孩子再放左孩子，左邊才會先被處理。

原創例子 A 的根 8 左孩 2、右孩 5；B 的根 9 左孩 7、7 左孩 2，根的右孩 5。A、B 都讀出 `[2,5]`，答案 true。用集合不行，因為 `[2,5]` 和 `[5,2]` 應不同。

```kotlin
import java.util.ArrayDeque
class Solution {
    fun leafSimilar(root1: TreeNode?, root2: TreeNode?): Boolean {
        return leaves(root1) == leaves(root2)
    }
    private fun leaves(root: TreeNode?): List<Int> {
        val result = mutableListOf<Int>()
        val stack = ArrayDeque<TreeNode>()
        root?.let { stack.addLast(it) }
        while (stack.isNotEmpty()) {
            val node = stack.removeLast()
            if (node.left == null && node.right == null) result.add(node.`val`)
            node.right?.let { stack.addLast(it) }
            node.left?.let { stack.addLast(it) }
        }
        return result
    }
}
```

**複雜度：** n、m 為兩棵樹節點數，時間及最壞空間 O(n+m)。**常見錯誤：** 只有一個孩子也當成葉子。**自測：** 根值不同一定 false 嗎？**答案：** 不一定，根不是葉子時其值不參與比較。

## 1448. Count Good Nodes in Binary Tree

**難度：Medium** · [英文原題](https://leetcode.com/problems/count-good-nodes-in-binary-tree/) · [官方中文](https://leetcode.cn/problems/count-good-nodes-in-binary-tree/)

### 中文題意（自行改寫，非逐字翻譯）

從根走到某節點，若途中沒有比它更大的值，它就是 good node。回傳個數。節點數 1–100,000，值在 ±10,000。

### 白話思路與手算

每個節點回頭重查祖先很慢。往下走時隨身攜帶「到目前最大的值」就好。每個分支拿自己的紀錄，兄弟分支互不影響。相等也合格。

原創例子：根 5，左孩 3，3 的左孩 6，根右孩 5。走 `5→3→6` 的最大紀錄為 5、5、6，合格為 5、6；右邊的 5 也合格，答案 3。

```kotlin
import java.util.ArrayDeque
class Solution {
    fun goodNodes(root: TreeNode?): Int {
        if (root == null) return 0
        val stack = ArrayDeque<Pair<TreeNode, Int>>()
        stack.addLast(root to Int.MIN_VALUE)
        var count = 0
        while (stack.isNotEmpty()) {
            val (node, maximum) = stack.removeLast()
            if (node.`val` >= maximum) count++
            val nextMaximum = maxOf(maximum, node.`val`)
            node.left?.let { stack.addLast(it to nextMaximum) }
            node.right?.let { stack.addLast(it to nextMaximum) }
        }
        return count
    }
}
```

**複雜度：** n 為節點數、h 為高度，時間 O(n)，堆疊空間 O(h)，最壞 O(n)。**常見錯誤：** 用整棵樹共用的一個最大值，讓左邊污染右邊。**自測：** 全樹值都等於 7 呢？**答案：** 每一個都合格。

## 437. Path Sum III

**難度：Medium** · [英文原題](https://leetcode.com/problems/path-sum-iii/) · [官方中文](https://leetcode.cn/problems/path-sum-iii/)

### 中文題意（自行改寫，非逐字翻譯）

數出總和等於 targetSum 的向下路徑，可以從任何節點開始、任何後代結束，但不能往上或跨兄弟。最多 1,000 個節點，值可到 ±10億，targetSum 在 ±1,000。

### 白話思路與手算

從每個節點各往下試一次，最壞 O(n²)。改用前綴和：從根累積到此處是 sum，如果祖先之前曾累積到 `sum-target`，兩者相減的那段就符合。

原創例子一條鏈 `2→1→-1→2`，target=2。四條合格路徑是第一個 `[2]`、`[2,1,-1]`、`[1,-1,2]`、最後 `[2]`。進入節點先查字典，再把本次 sum 加入；離開節點時扣回，才能避免另一分支被誤當祖先。初始 `0→1` 表示根之前的空前綴，讓從根開始的路徑也能被數到。

本版堆疊事件的 leaving=true 表示「孩子都處理完，現在離開」。最後放進去的先執行，所以先排離開事件、再排孩子。

```kotlin
import java.util.ArrayDeque
class Solution {
    private data class Event(val node: TreeNode, val sum: Long, val leaving: Boolean)
    fun pathSum(root: TreeNode?, targetSum: Int): Int {
        if (root == null) return 0
        val counts = hashMapOf(0L to 1)
        val stack = ArrayDeque<Event>()
        stack.addLast(Event(root, 0L, false))
        var answer = 0
        while (stack.isNotEmpty()) {
            val event = stack.removeLast()
            if (event.leaving) {
                val remaining = counts.getValue(event.sum) - 1
                if (remaining == 0) counts.remove(event.sum)
                else counts[event.sum] = remaining
                continue
            }
            val sum = event.sum + event.node.`val`.toLong()
            answer += counts[sum - targetSum.toLong()] ?: 0
            counts[sum] = (counts[sum] ?: 0) + 1
            stack.addLast(Event(event.node, sum, true))
            event.node.right?.let { stack.addLast(Event(it, sum, false)) }
            event.node.left?.let { stack.addLast(Event(it, sum, false)) }
        }
        return answer
    }
}
```

**複雜度：** n 為節點數、h 為高度，雜湊操作平均 O(1) 時，總時間 O(n)、空間 O(h)。**常見錯誤：** sum 用 Int 溢位；忘記離開時扣除；負數存在卻用「超過目標就停止」。**自測：** 為何存出現次數而非 Set？**答案：** 不同祖先可能有相同前綴和，代表多條不同路徑。

## 1372. Longest ZigZag Path in a Binary Tree

**難度：Medium** · [英文原題](https://leetcode.com/problems/longest-zigzag-path-in-a-binary-tree/) · [官方中文](https://leetcode.cn/problems/longest-zigzag-path-in-a-binary-tree/)

### 中文題意（自行改寫，非逐字翻譯）

選任意起點往下走，方向必須左、右、左、右交替，求最多走幾條邊。單節點是 0。節點 1–50,000，值為 1–100，值本身不影響路徑。

### 白話思路與手算

每個起點都重新走會重複。對每個節點記兩件事：到這裡最後一步向左的最長長度 left，以及最後一步向右的最長長度 right。走到左孩時，新 left=原 right+1；新 right=0，因為尚未往右走。

原創形狀 `根 --左→ A --右→ B --左→ C`，狀態由 `(0,0)`、`(1,0)`、`(0,2)`、`(3,0)`，答案 3。若再次往左，會自動從上一個節點重新起算為 1，因此不漏掉任意起點。

```kotlin
import java.util.ArrayDeque
class Solution {
    private data class State(val node: TreeNode, val left: Int, val right: Int)
    fun longestZigZag(root: TreeNode?): Int {
        if (root == null) return 0
        val stack = ArrayDeque<State>()
        stack.addLast(State(root, 0, 0))
        var best = 0
        while (stack.isNotEmpty()) {
            val s = stack.removeLast()
            best = maxOf(best, s.left, s.right)
            s.node.left?.let { stack.addLast(State(it, s.right + 1, 0)) }
            s.node.right?.let { stack.addLast(State(it, 0, s.left + 1)) }
        }
        return best
    }
}
```

**複雜度：** n 為節點數、h 為高度，時間 O(n)，空間 O(h)。**常見錯誤：** 相同方向接續累加。**自測：** 10 個節點全都只有左孩，答案？**答案：** 1。

**難度：Medium** · [英文原題](https://leetcode.com/problems/lowest-common-ancestor-of-a-binary-tree/) · [官方中文](https://leetcode.cn/problems/lowest-common-ancestor-of-a-binary-tree/)

### 中文題意（自行改寫，非逐字翻譯）

給兩個不同且確實存在的節點 p、q，找同時包含它們、位置最深的祖先，節點自己也算自己的祖先。節點數 2–100,000，值唯一，在 ±10億。

### 白話思路與手算

可以遞迴向左右問「有沒有 p/q」，但為了深樹安全，本版先建立每個節點的父節點表。把 p 往根走過的所有人放集合，再從 q 往上，第一個在集合裡的人就是答案。因為 q 由下往上走，首次相遇一定是最低共同點。

原創例子根 8、左孩 4、右孩 12，4 的右孩 6。p=6、q=12：p 的祖先是 `{6,4,8}`；q 依序 12、8，第一個相遇在 8。

```kotlin
import java.util.ArrayDeque
class Solution {
    fun lowestCommonAncestor(root: TreeNode?, p: TreeNode?, q: TreeNode?): TreeNode? {
        if (root == null || p == null || q == null) return null
        val parent = HashMap<TreeNode, TreeNode?>()
        val stack = ArrayDeque<TreeNode>()
        parent[root] = null
        stack.addLast(root)
        while (!parent.containsKey(p) || !parent.containsKey(q)) {
            val node = stack.removeLast()
            node.left?.let { parent[it] = node; stack.addLast(it) }
            node.right?.let { parent[it] = node; stack.addLast(it) }
        }
        val ancestors = HashSet<TreeNode>()
        var current: TreeNode? = p
        while (current != null) {
            ancestors.add(current)
            current = parent[current]
        }
        current = q
        while (current != null && current !in ancestors) current = parent[current]
        return current
    }
}
```

**複雜度：** n 為節點數，平均時間 O(n)，空間 O(n)。**常見錯誤：** 以 BST 的大小規則搜尋；本題只保證一般二元樹。**自測：** p 本來就是 q 的祖先呢？**答案：** 回傳 p。

### 白話思路與手算

不是一路沿 right 走到底，因為右子樹可能比較矮。用 BFS 一層一層看，孩子左先右後排隊，每層最後拿出來的就是最右邊。

```kotlin
import java.util.ArrayDeque
class Solution {
    fun rightSideView(root: TreeNode?): List<Int> {
        val answer = mutableListOf<Int>()
        if (root == null) return answer
        val queue = ArrayDeque<TreeNode>()
        queue.addLast(root)
        while (queue.isNotEmpty()) {
            val count = queue.size
            repeat(count) { index ->
                val node = queue.removeFirst()
                if (index == count - 1) answer.add(node.`val`)
                node.left?.let { queue.addLast(it) }
                node.right?.let { queue.addLast(it) }
            }
        }
        return answer
    }
}
```

## 1161. Maximum Level Sum of a Binary Tree

**難度：Medium** · [英文原題](https://leetcode.com/problems/maximum-level-sum-of-a-binary-tree/) · [官方中文](https://leetcode.cn/problems/maximum-level-sum-of-a-binary-tree/)

### 中文題意（自行改寫，非逐字翻譯）

每層的值相加，回傳和最大的層號，根層號為 1；同分取較小層號。節點 1–10,000，值在 ±100,000。

### 白話思路與手算

沿用 BFS，這次每層累加，而不是只取最後一個。原創例子根 -2、左右孩 -1 和 -1，第二層和也是 -2；第三層只有 -5。最大和 -2 同分，回傳 1。只在「嚴格更大」時更新答案，就自然保留較早層。

```kotlin
import java.util.ArrayDeque
class Solution {
    fun maxLevelSum(root: TreeNode?): Int {
        if (root == null) return 0
        val queue = ArrayDeque<TreeNode>()
        queue.addLast(root)
        var level = 0
        var bestLevel = 0
        var bestSum = Long.MIN_VALUE
        while (queue.isNotEmpty()) {
            level++
            var sum = 0L
            repeat(queue.size) {
                val node = queue.removeFirst()
                sum += node.`val`.toLong()
                node.left?.let { queue.addLast(it) }
                node.right?.let { queue.addLast(it) }
            }
            if (sum > bestSum) { bestSum = sum; bestLevel = level }
        }
        return bestLevel
    }
}
```

**複雜度：** n 為節點數、w 為最大層寬，時間 O(n)，空間 O(w)。`repeat(queue.size)` 的次數進入前就計算好，不會隨新孩子變大。**常見錯誤：** bestSum 初始化為 0，導致全負數錯誤。**自測：** 回傳的是最大總和嗎？**答案：** 不是，是該層的編號。

### 中文題意（自行改寫，非逐字翻譯）

### 白話思路與手算

BST 的重要規則：左子樹每個值都比目前節點小，右子樹每個值都比較大。因此不用把左右都找遍。原創例子根 10、左孩 5、右孩 15，5 右孩 7；找 7 時 `10→5→7`。7 比 10 小，所以整個右子樹都能排除；比 5 大，所以往右。每次排除的那側依規則不可能含目標。

```kotlin
class Solution {
    fun searchBST(root: TreeNode?, `val`: Int): TreeNode? {
        var node = root
        while (node != null) {
            if (node.`val` == `val`) return node
            node = if (`val` < node.`val`) node.left else node.right
        }
        return null
    }
}
```

**複雜度：** h 為高度，時間 O(h)，空間 O(1)。只有平衡時 h 才約 log n；長鏈最壞 O(n)。**常見錯誤：** 回傳新建的單一節點，遺失原有孩子。**自測：** 能用這方法搜尋任意二元樹嗎？**答案：** 不行，必須有 BST 大小規則。

## 450. Delete Node in a BST

**難度：Medium** · [英文原題](https://leetcode.com/problems/delete-node-in-a-bst/) · [官方中文](https://leetcode.cn/problems/delete-node-in-a-bst/)

### 中文題意（自行改寫，非逐字翻譯）

從 BST 刪除 key，回傳仍合法的 BST 根；找不到則不變。最多 10,000 個節點，可空，值唯一，節點與 key 在 ±100,000。期望時間 O(樹高)。

### 白話思路與手算

先搜尋。沒有孩子直接移除；只有一個孩子，讓孩子接替。兩個孩子時，不能任意拉一個上來；找右子樹中最小值，也就是一直向左的節點，將它的值搬到待刪位置，再移除原來那個節點。它沒有左孩，所以最後只剩簡單情況。

原創例子根 8、左孩 3、右孩 11，11 左孩 9。刪 8：右邊最小為 9，把根值改為 9，再把 11.left 設 null，結果根 9、孩子 3 與 11。9 大於所有左邊、小於其餘右邊，BST 規則仍成立。

```kotlin
class Solution {
    fun deleteNode(root: TreeNode?, key: Int): TreeNode? {
        var parent: TreeNode? = null
        var node = root
        while (node != null && node.`val` != key) {
            parent = node
            node = if (key < node.`val`) node.left else node.right
        }
        var target = node ?: return root
        if (target.left != null && target.right != null) {
            var successorParent = target
            var successor = target.right!!
            while (successor.left != null) {
                successorParent = successor
                successor = successor.left!!
            }
            target.`val` = successor.`val`
            parent = successorParent
            target = successor
        }
        val child = target.left ?: target.right
        val p = parent ?: return child // 刪的是根，根可能改變
        if (p.left === target) p.left = child else p.right = child
        return root
    }
}
```

**複雜度：** h 為高度，時間 O(h)，額外空間 O(1)，修改輸入樹。`===` 比較是不是同一個節點物件。**常見錯誤：** 只改值卻沒刪掉原後繼，留下重複值。**自測：** 後繼可不可以有右孩？**答案：** 可以，刪它時要把右孩接回父親。

### 中文題意（自行改寫，非逐字翻譯）

只有房間 0 一開始可進入，每個 rooms[i] 存該房的鑰匙編號。判斷能否拜訪所有房間。房間 2–1,000 間，總鑰匙 1–3,000 把；每間房內鑰匙不重複。

### 白話思路與手算

房間是圖的節點，鑰匙是單向邊。「到過 A 可以去 B」不代表 B 能回 A。用待辦堆疊把新房間排進去，每間只處理一次，否則遇到彼此有鑰匙會繞圈。

原創例子 `rooms=[[2],[0],[1]]`：從 0 拿 2，進 2 拿 1，再進 1；雖然又拿 0，但已看過就跳過，答案 true。所有能由 0 經鑰匙鏈到達的房間都會加入待辦，因此最後全部 seen 才能成功。

```kotlin
import java.util.ArrayDeque
class Solution {
    fun canVisitAllRooms(rooms: List<List<Int>>): Boolean {
        val seen = BooleanArray(rooms.size)
        val stack = ArrayDeque<Int>()
        seen[0] = true
        stack.addLast(0)
        while (stack.isNotEmpty()) {
            val room = stack.removeLast()
            for (key in rooms[room]) {
                if (!seen[key]) {
                    seen[key] = true
                    stack.addLast(key)
                }
            }
        }
        return seen.all { it }
    }
}
```

**複雜度：** V 為房間數、E 為鑰匙總數，時間 O(V+E)，空間 O(V)。**常見錯誤：** 看過所有鑰匙編號就宣稱成功，卻沒確認存鑰匙的房能不能進。**自測：** 1 房的鑰匙只有 1 房自己有，0 拿不到它，能進嗎？**答案：** 不能。

**難度：Medium** · [英文原題](https://leetcode.com/problems/number-of-provinces/) · [官方中文](https://leetcode.cn/problems/number-of-provinces/)

### 中文題意（自行改寫，非逐字翻譯）

n×n 的 0/1 表格表示城市直接相連；連線對稱、自己連自己。直接或間接連成一群稱為一個省，求群數。n 為 1–200。

### 白話思路與手算

不能只數直接邊，也不能只從城市 0 開始。依序檢查每個城市：如果沒去過，它一定屬於一個還沒數過的新群；答案加一，再把整群走完標記。

原創例子四城連成 `0—2` 與 `1—3`，矩陣各列為 `1010 / 0101 / 1010 / 0101`。從 0 染到 2，群數 1；從 1 染到 3，群數 2；2、3 已看過，跳過。每群只在首次遇到時加一。

```kotlin
import java.util.ArrayDeque
class Solution {
    fun findCircleNum(isConnected: Array<IntArray>): Int {
        val n = isConnected.size
        val seen = BooleanArray(n)
        val stack = ArrayDeque<Int>()
        var provinces = 0
        for (start in 0 until n) {
            if (seen[start]) continue
            provinces++
            seen[start] = true
            stack.addLast(start)
            while (stack.isNotEmpty()) {
                val city = stack.removeLast()
                for (next in 0 until n) {
                    if (isConnected[city][next] == 1 && !seen[next]) {
                        seen[next] = true
                        stack.addLast(next)
                    }
                }
            }
        }
        return provinces
    }
}
```

**複雜度：** n 為城市數，時間 O(n²)，因為每個城市都掃一整列；額外空間 O(n)。**常見錯誤：** 把對角線的 1 各算一個省。**自測：** 完全沒有城市間道路，n 個城市幾省？**答案：** n 省。

### 中文題意（自行改寫，非逐字翻譯）

n 個城市、n−1 條單向路，忽略方向後形成一棵樹。最少反轉幾條，才能讓每城到達 0？n 為 2–50,000，connections 的 `[a,b]` 表示 a→b。

### 白話思路與手算

雖然道路單向，探索時要能看見兩端，否則找不到朝 0 的那些路。建立兩種紀錄：順著原方向走，標記 cost=1；逆著原方向走，標記 cost=0。從 0 向外探索，若原方向也向外，就必須翻轉。

原創例子 `0→1、2→1、2→3`：由 0 探索到 1，翻 0→1；從 1 到 2 原路已朝根，不翻；從 2 到 3 再翻，答案 2。樹上每城通往根只有一條路，所以每條朝外邊都非翻不可；翻完也確實足夠。

```kotlin
import java.util.ArrayDeque
class Solution {
    fun minReorder(n: Int, connections: Array<IntArray>): Int {
        val graph = Array(n) { mutableListOf<Pair<Int, Int>>() }
        for (edge in connections) {
            graph[edge[0]].add(edge[1] to 1)
            graph[edge[1]].add(edge[0] to 0)
        }
        val seen = BooleanArray(n)
        val stack = ArrayDeque<Int>()
        stack.addLast(0)
        seen[0] = true
        var changes = 0
        while (stack.isNotEmpty()) {
            val city = stack.removeLast()
            for ((next, cost) in graph[city]) {
                if (!seen[next]) {
                    seen[next] = true
                    changes += cost
                    stack.addLast(next)
                }
            }
        }
        return changes
    }
}
```

**複雜度：** n 為城市數，時間與空間 O(n)。**常見錯誤：** 誤以為要讓 0 能到每城，方向完全反過來。**自測：** 此證明能直接用在任意有環圖嗎？**答案：** 不能，樹上唯一路徑的條件是關鍵。

## 399. Evaluate Division

**難度：Medium** · [英文原題](https://leetcode.com/problems/evaluate-division/) · [官方中文](https://leetcode.cn/problems/evaluate-division/)

### 中文題意（自行改寫，非逐字翻譯）

equations 與 values 給一些變數比例，求 queries 的比例，無法得知回傳 -1.0。等式和查詢各 1–20 筆，比例大於 0 且至多 20；資料無矛盾。未出現在等式的名字視為未知。

### 白話思路與手算

把變數當城市，比例當路上的乘數。如果 x/y=4，就建立 x→y 的 4 與 y→x 的 0.25。沿路相乘，中間變數會抵消：`x/y × y/z = x/z`。

原創例子 x/y=4、y/z=0.5。走 x→y→z，乘數 `1→4→2`，所以 x/z=2；z/x=0.5；未知 u/u 仍是 -1。每次查詢從頭建立 seen，避免另一查詢的紀錄干擾。

```kotlin
import java.util.ArrayDeque
class Solution {
    fun calcEquation(equations: List<List<String>>, values: DoubleArray,
                     queries: List<List<String>>): DoubleArray {
        val graph = HashMap<String, MutableList<Pair<String, Double>>>()
        for (i in equations.indices) {
            val a = equations[i][0]
            val b = equations[i][1]
            graph.getOrPut(a) { mutableListOf() }.add(b to values[i])
            graph.getOrPut(b) { mutableListOf() }.add(a to 1.0 / values[i])
        }
        fun search(start: String, end: String): Double {
            if (start !in graph || end !in graph) return -1.0
            val queue = ArrayDeque<Pair<String, Double>>()
            val seen = hashSetOf(start)
            queue.addLast(start to 1.0)
            while (queue.isNotEmpty()) {
                val (node, ratio) = queue.removeFirst()
                if (node == end) return ratio
                for ((next, weight) in graph.getValue(node)) {
                    if (seen.add(next)) queue.addLast(next to ratio * weight)
                }
            }
            return -1.0
        }
        return DoubleArray(queries.size) { search(queries[it][0], queries[it][1]) }
    }
}
```

**複雜度：** V 為變數數、E 為等式數、Q 為查詢數；平均時間 O(E+Q(V+E))，額外空間 O(V+E)，輸出 O(Q)。**常見錯誤：** 比例相加；忘了反向邊要取倒數。**自測：** 已知 x，x/x 呢？**答案：** 1.0。

## 1926. Nearest Exit from Entrance in Maze

**難度：Medium** · [英文原題](https://leetcode.com/problems/nearest-exit-from-entrance-in-maze/) · [官方中文](https://leetcode.cn/problems/nearest-exit-from-entrance-in-maze/)

### 中文題意（自行改寫，非逐字翻譯）

迷宮 `.` 可走、`+` 是牆，從 entrance 上下左右一步一步走，找最近邊界空格所需步數，沒有則 -1。入口自己不算出口。列、欄各 1–100，入口保證可走。

### 白話思路與手算

DFS 先找到的出口不一定最近。BFS 把距離 1 的全部看完，再看距離 2，所以首次找到的出口必定最短。格子排入佇列時立即標記，避免不同路線重複排入。

原創迷宮：

```text
+ + + +
+ S . .
+ + + +
S=(1,1)，先到 (1,2) 距離1，再到 (1,3) 距離2。
(1,3) 是邊界，所以答案 2。
```

```kotlin
import java.util.ArrayDeque
class Solution {
    fun nearestExit(maze: Array<CharArray>, entrance: IntArray): Int {
        val rows = maze.size
        val cols = maze[0].size
        val queue = ArrayDeque<IntArray>()
        val directions = intArrayOf(-1, 0, 1, 0, -1)
        queue.addLast(intArrayOf(entrance[0], entrance[1], 0))
        maze[entrance[0]][entrance[1]] = '+'
        while (queue.isNotEmpty()) {
            val current = queue.removeFirst()
            for (d in 0 until 4) {
                val r = current[0] + directions[d]
                val c = current[1] + directions[d + 1]
                if (r !in 0 until rows || c !in 0 until cols || maze[r][c] != '.') continue
                if (r == 0 || r == rows - 1 || c == 0 || c == cols - 1) return current[2] + 1
                maze[r][c] = '+'
                queue.addLast(intArrayOf(r, c, current[2] + 1))
            }
        }
        return -1
    }
}
```

**複雜度：** R、C 為列欄數，時間與額外空間 O(RC)。此版會改寫 maze；要重跑時需重新建立或複製輸入。**常見錯誤：** 入口在邊界就回傳 0。**自測：** 可斜走嗎？**答案：** 不行，只能四個方向。

## 994. Rotting Oranges

**難度：Medium** · [英文原題](https://leetcode.com/problems/rotting-oranges/) · [官方中文](https://leetcode.cn/problems/rotting-oranges/)

### 中文題意（自行改寫，非逐字翻譯）

格子 0 是空地、1 是新鮮橘子、2 是爛橘子。每分鐘所有爛橘子同時感染上下左右新鮮橘子，求全部沒有新鮮橘子的最少分鐘；做不到為 -1。列欄各 1–10。

### 白話思路與手算

不能每顆爛橘子各自完整傳染後才處理下一顆，因為現實是同時發生。把一開始所有爛橘子一起排隊，稱為多起點 BFS。每輪只處理本分鐘已爛的，新感染的留下一輪。

原創例子 `[2,1,1,1,2]`：0 分鐘左右兩端爛；1 分鐘變 `[2,2,1,2,2]`；2 分鐘全部爛，答案 2。另計 fresh，感染就扣一，避免每分鐘重掃整張圖。

```kotlin
import java.util.ArrayDeque
class Solution {
    fun orangesRotting(grid: Array<IntArray>): Int {
        val rows = grid.size
        val cols = grid[0].size
        val queue = ArrayDeque<Pair<Int, Int>>()
        var fresh = 0
        for (r in 0 until rows) for (c in 0 until cols) {
            if (grid[r][c] == 1) fresh++
            if (grid[r][c] == 2) queue.addLast(r to c)
        }
        val directions = intArrayOf(-1, 0, 1, 0, -1)
        var minutes = 0
        while (queue.isNotEmpty() && fresh > 0) {
            repeat(queue.size) {
                val (r, c) = queue.removeFirst()
                for (d in 0 until 4) {
                    val nr = r + directions[d]
                    val nc = c + directions[d + 1]
                    if (nr in 0 until rows && nc in 0 until cols && grid[nr][nc] == 1) {
                        grid[nr][nc] = 2
                        fresh--
                        queue.addLast(nr to nc)
                    }
                }
            }
            minutes++
        }
        return if (fresh == 0) minutes else -1
    }
}
```

**複雜度：** R、C 為列欄數，時間與額外空間 O(RC)，會修改 grid。**常見錯誤：** 沒新鮮橘子還回傳 1；空地也傳染。**自測：** `[2,0,1]`？**答案：** -1，感染不能跨空地。

## 215. Kth Largest Element in an Array

**難度：Medium** · [英文原題](https://leetcode.com/problems/kth-largest-element-in-an-array/) · [官方中文](https://leetcode.cn/problems/kth-largest-element-in-an-array/)

### 中文題意（自行改寫，非逐字翻譯）

找降冪排列第 k 個數，重複數字也佔名次。`1 ≤ k ≤ n ≤ 100,000`，數值在 ±10,000。題目希望不靠完整排序。

### 白話思路與手算

完整排序是 O(n log n)。只保留目前最大的 k 個就夠；最小 Heap 的箱口是這 k 個中最小的，也就是第 k 大。每讀一數先放入，超過 k 就拿掉最小的。被拿掉的已有至少 k 個數不小於它，不可能再擠進前 k。

原創例子 `[8,2,8,5]`、k=2：保留集合依序 `[8]`、`[2,8]`、`[8,8]`、`[8,8]`，答案 8。這裡列出的集合為方便閱讀排序過，PriorityQueue 內部本身不保證全部有序。

```kotlin
import java.util.PriorityQueue
class Solution {
    fun findKthLargest(nums: IntArray, k: Int): Int {
        val heap = PriorityQueue<Int>()
        for (number in nums) {
            heap.offer(number)
            if (heap.size > k) heap.poll()
        }
        return heap.peek()
    }
}
```

**複雜度：** n 為元素數，時間 O(n log(k+1))，空間 O(k)。heap 的 offer/poll 是 O(log 大小)，peek 是 O(1)。**常見錯誤：** 用 Set 去重，改變名次。**自測：** k=1，箱口是最大還最小？**答案：** 全部輸入的最大值，因為其他較小值都已被丟掉。

## 2336. Smallest Number in Infinite Set

**難度：Medium** · [英文原題](https://leetcode.com/problems/smallest-number-in-infinite-set/) · [官方中文](https://leetcode.cn/problems/smallest-number-in-infinite-set/)

### 中文題意（自行改寫，非逐字翻譯）

設計 SmallestInfiniteSet，初始含所有正整數。popSmallest 移除並回傳最小值；addBack 把已移除的值放回，已存在則不做事。總操作至多 1,000 次，放回值為 1–1,000。

### 白話思路與手算

不用真的存無限個數。next 表示「從未取出過的最小數」，next 後面都還在。比 next 小卻被放回的少量數，放 TreeSet：它同時支援去重與取最小。

原創操作：pop→1、pop→2，next=3；addBack(2) 兩次，集合仍只有 `{2}`；pop→2，再 pop→3。永遠先取放回集合，因為其中每個數都小於 next。

```kotlin
import java.util.TreeSet
class SmallestInfiniteSet() {
    private var next = 1
    private val returned = TreeSet<Int>()
    fun popSmallest(): Int {
        if (returned.isNotEmpty()) return returned.pollFirst()!!
        val answer = next
        next++
        return answer
    }
    fun addBack(num: Int) {
        if (num < next) returned.add(num)
    }
}
```

**複雜度：** b 為已放回而尚未取出的數量，addBack 與有放回數時的 pop 最壞 O(log(b+1))；直接取 next 為 O(1)。空間 O(b)。**常見錯誤：** 用只有 Heap 的容器卻沒防重複。**自測：** next=5 時 addBack(8)？**答案：** 不用動，8 本來就在未取出的尾段。

## 2542. Maximum Subsequence Score

**難度：Medium** · [英文原題](https://leetcode.com/problems/maximum-subsequence-score/) · [官方中文](https://leetcode.cn/problems/maximum-subsequence-score/)

### 中文題意（自行改寫，非逐字翻譯）

兩個等長陣列，選同一組恰好 k 個索引，分數是 nums1 選中值的總和，乘上 nums2 選中值的最小值。求最大分數。`1 ≤ k ≤ n ≤ 100,000`，值為 0–100,000。

### 白話思路與手算

枚舉所有 k 人組合會爆炸。難點是「和」與「最小值」一起變。先依 nums2 從大到小處理，輪到值 b 時，之前看過的人其 nums2 都至少是 b。現在強制選本次這人當最小值來源，另外從先前的人挑 nums1 最大的 k−1 個，就能得到這個條件下最佳和。

Heap 保留先前最大的 k−1 個 nums1。每輪先加本次，若湊滿 k 就計分，然後丟掉最小，恢復 k−1 人，供下一輪使用。這樣計分時本次人物必定在內，乘數確實是 b。任何最佳組合都有一位在排序中最後出現的人；輪到他時，我們挑的其餘 k−1 人總和至少和最佳組合一樣好，因此不會漏掉最優答案。

原創例子 nums1=`[4,2,6]`、nums2=`[3,5,2]`、k=2。排序後 `(2,5),(4,3),(6,2)`：先存 2；加入 4 得 `(2+4)×3=18`，丟 2 留 4；加入 6 得 `(4+6)×2=20`，答案 20。兩陣列要綁成一組排序，不能各自排序。

```kotlin
import java.util.PriorityQueue
class Solution {
    fun maxScore(nums1: IntArray, nums2: IntArray, k: Int): Long {
        val order = nums1.indices.sortedByDescending { nums2[it] }
        val heap = PriorityQueue<Int>()
        var sum = 0L
        var best = 0L
        for (i in order) {
            heap.offer(nums1[i])
            sum += nums1[i].toLong()
            if (heap.size == k) {
                best = maxOf(best, sum * nums2[i].toLong())
                sum -= heap.poll().toLong()
            }
        }
        return best
    }
}
```

**複雜度：** n 為長度，時間 O(n log n+n log(k+1))，可寫 O(n log n)；排序索引 O(n)、Heap O(k)，總額外空間 O(n+k)。**常見錯誤：** 用 Int 存總和或分數，最大可達 10¹⁵；丟元素後才用剩餘 k−1 人計分。**自測：** k=1 時分數？**答案：** 每個索引的 nums1[i]×nums2[i]，取最大。

## 2462. Total Cost to Hire K Workers

**難度：Medium** · [英文原題](https://leetcode.com/problems/total-cost-to-hire-k-workers/) · [官方中文](https://leetcode.cn/problems/total-cost-to-hire-k-workers/)

### 中文題意（自行改寫，非逐字翻譯）

每輪只能從剩下人員的前 candidates 人與後 candidates 人選費用最低者；同費用選索引較小者。選走一人後重新形成候選範圍，僱用 k 人求總費用。n、費用皆至多 100,000，k 與 candidates 在 1–n。

### 白話思路與手算

每輪重新掃兩端會慢。用一個 Heap 裝目前可選的人，存「費用、原索引、來自哪一側」。兩個指標 left/right 指向中間尚未加入候選的人；某側選走一人，就從同側補一人。即使刪除造成目前索引改變，剩下人原索引大小順序不變，所以仍可用原索引破同分。

原創例子 `[7,2,9,1,6]`、k=3、candidates=1：先能選 7、6，選 6 補右側 1；選 1 補右側 9；最後從 7、9 選 7，總和 14。雖然 2 很便宜，但前面 7 還沒被選時，2 不能提前參選。

只有 `left<=right` 才補人，防止兩端交會時重複放入同一人。Heap 每次取出規則指定的最小候選，補人後又剛好恢復合法候選集合，所以逐輪結果符合題目。

```kotlin
import java.util.PriorityQueue
class Solution {
    private data class Worker(val cost: Int, val index: Int, val fromLeft: Boolean)
    fun totalCost(costs: IntArray, k: Int, candidates: Int): Long {
        val heap = PriorityQueue<Worker>(compareBy<Worker> { it.cost }.thenBy { it.index })
        var left = 0
        var right = costs.lastIndex
        repeat(candidates) {
            if (left <= right) {
                heap.offer(Worker(costs[left], left, true))
                left++
            }
        }
        repeat(candidates) {
            if (left <= right) {
                heap.offer(Worker(costs[right], right, false))
                right--
            }
        }
        var total = 0L
        repeat(k) {
            val worker = heap.poll()
            total += worker.cost.toLong()
            if (left <= right) {
                if (worker.fromLeft) {
                    heap.offer(Worker(costs[left], left, true))
                    left++
                } else {
                    heap.offer(Worker(costs[right], right, false))
                    right--
                }
            }
        }
        return total
    }
}
```

**複雜度：** n 為人數、c 為 candidates、s=min(n,2c)，時間 O((s+k) log(s+1))，空間 O(s)。總費用用 Long。**常見錯誤：** 直接取全陣列最便宜 k 人；兩端重疊重複入隊；費用相同未比較索引。**自測：** c≥n 時會重複僱同一人嗎？**答案：** 不會，left/right 檢查使每個原索引只進隊一次。
