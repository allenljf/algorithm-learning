## 1768. Merge Strings Alternately

難度：Easy｜[英文原題](https://leetcode.com/problems/merge-strings-alternately/)｜[官方中文](https://leetcode.cn/problems/merge-strings-alternately/)

**中文題意（自行改寫）**：給你兩個小寫英文字串，從第一個開始，兩邊輪流拿一個字母放進答案。某邊先用完，另一邊剩下的全部接在後面。回傳新字串。

**白話思路**：想成兩列人交替進場。索引 `i` 是「現在輪到第幾位」，不是字母本身。不必真的刪掉原字串的字母；往前移動索引就代表已處理。只要有一邊還有人，就繼續。

**手算**：`word1="dog", word2="xy"`。第 0 輪拿 d、x → `dx`；第 1 輪拿 o、y → `dxoy`；第 2 輪只拿 g → `dxoyg`。每個字母剛好拿一次。

```kotlin
class Solution {
    fun mergeAlternately(word1: String, word2: String): String {
        val answer = StringBuilder()
        var i = 0
        while (i < word1.length || i < word2.length) {
            if (i < word1.length) answer.append(word1[i])
            if (i < word2.length) answer.append(word2[i])
            i++
        }
        return answer.toString()
    }
}
```

**為什麼對**：每一輪都先放第一邊、再放第二邊，且兩邊的第 i 個字母只會在第 i 輪放入。時間 O(a+b)，空間 O(a+b)，a、b 是兩字串長度。

**常見錯誤**：條件寫成 `&&`，會在較短的一邊用完時提早停止。反覆 `answer += char` 會建立許多新字串，改用 `StringBuilder`。

**理解自測**：`"a"` 與 `"bcd"` 的結果？答案：`"abcd"`，不是 `"ab"`。

## 1071. Greatest Common Divisor of Strings

難度：Easy｜[英文原題](https://leetcode.com/problems/greatest-common-divisor-of-strings/)｜[官方中文](https://leetcode.cn/problems/greatest-common-divisor-of-strings/)

**中文題意（自行改寫）**：找最長的一小段字串，使它重複若干次後，可以分別組出兩個輸入字串。必須完整拼出，不能剩字；不存在時回傳空字串。輸入非空、都是大寫英文。

**白話思路**：把字串當成重複貼的磁磚。若兩串來自同一種磁磚，`str1+str2` 與 `str2+str1` 應該相同；不相同就不可能共用。相同時，答案長度是兩個長度的最大公因數（GCD）：能同時整除兩個長度的最大整數。

**手算**：`"XYXYXYXY"` 長 8，`"XYXYXY"` 長 6。兩種接法都一樣。8 ÷ 6 餘 2，6 ÷ 2 餘 0，因此 GCD=2，取前兩字 `"XY"`。輾轉相除就是反覆把「較大的數」換成餘數，直到沒有餘數。

```kotlin
class Solution {
    fun gcdOfStrings(str1: String, str2: String): String {
        if (str1 + str2 != str2 + str1) return ""
        var a = str1.length
        var b = str2.length
        while (b != 0) {
            val remainder = a % b
            a = b
            b = remainder
        }
        return str1.substring(0, a)
    }
}
```

**為什麼對**：相接可交換的非空字串可由同一最小重複單位組成；要切出能重複覆蓋兩串的最長區塊，區塊長度就取長度的 GCD。第一次先學會模擬餘數即可，不必把這題當作字串題的通用公式。時間 O(a+b)，空間 O(a+b)，主要成本是建立、比較串接字串。

**常見錯誤**：只算長度 GCD，卻沒檢查字母排列。長度相同不代表內容相同。

**理解自測**：`"AAAA"` 與 `"AA"` 答案是 A 還是 AA？答案：AA，因為要求最長。

## 1431. Kids With the Greatest Number of Candies

難度：Easy｜[英文原題](https://leetcode.com/problems/kids-with-the-greatest-number-of-candies/)｜[官方中文](https://leetcode.cn/problems/kids-with-the-greatest-number-of-candies/)

**中文題意（自行改寫）**：陣列是每個小孩的糖果數。逐個假設「全部額外糖果只給這位」，判斷他能否達到全場最多，並列也算。回傳每個人的 Boolean 結果。每次假設互相獨立。

**白話思路**：最直接是每位都跟所有其他人比，會重複比較。先找目前最高門檻，再讓每個人加上額外糖果去比門檻即可。

**手算**：`[1,4,2]`、額外 2。門檻是 4；1+2=3 不夠，4+2=6 可以，2+2=4 並列可以 → `[false,true,true]`。

```kotlin
class Solution {
    fun kidsWithCandies(candies: IntArray, extraCandies: Int): List<Boolean> {
        var maximum = candies[0]
        for (candy in candies) maximum = maxOf(maximum, candy)
        val answer = mutableListOf<Boolean>()
        for (candy in candies) {
            answer.add(candy + extraCandies >= maximum)
        }
        return answer
    }
}
```

**為什麼對**：其他人的糖果不變，只要這個人的新數量不低於原本最大值，他就一定達到最多。掃兩遍仍然是 O(n)，不是 O(n²)；輸出空間 O(n)。

**常見錯誤**：用 `>` 排除了並列；或真的修改每個人的糖果，讓前一次假設污染下一次。

**理解自測**：為何不用為每個人重算最大值？答案：比較的門檻固定，且每次只是假設。

## 605. Can Place Flowers

難度：Easy｜[英文原題](https://leetcode.com/problems/can-place-flowers/)｜[官方中文](https://leetcode.cn/problems/can-place-flowers/)

**中文題意（自行改寫）**：0 是空位，1 是已有花的位置；原本的花互不相鄰。判斷能否再種 n 朵，仍保持任何兩朵不相鄰。n 可以是 0。

**白話思路**：從左往右看，遇到自己和左右鄰居都空的格子就種。這叫貪心：先作眼前可確定不吃虧的選擇。最左可種位置先用掉，不會比把同一朵往右放更擠壓後面空間。

**手算**：`[0,0,0,0,0]` 要 3 朵。種索引 0 → `[1,0,0,0,0]`；跳過 1；種 2；跳過 3；種 4 → `[1,0,1,0,1]`，成功。

```kotlin
class Solution {
    fun canPlaceFlowers(flowerbed: IntArray, n: Int): Boolean {
        if (n == 0) return true
        var planted = 0
        for (i in flowerbed.indices) {
            val leftEmpty = i == 0 || flowerbed[i - 1] == 0
            val rightEmpty = i == flowerbed.lastIndex || flowerbed[i + 1] == 0
            if (flowerbed[i] == 0 && leftEmpty && rightEmpty) {
                flowerbed[i] = 1 // 讓後面的格子知道這裡已經種花
                planted++
                if (planted >= n) return true
            }
        }
        return false
    }
}
```

**為什麼對**：如果某種最優安排沒用最左可種格，將它的第一朵移到這格，與後面花朵的距離只會增加。因此可以放心先種。時間 O(m)，額外空間 O(1)，m 是花圃長度。本解法會修改輸入；需要保留時先 `copyOf()`，空間就變 O(m)。

**常見錯誤**：沒有記錄新種下的花，導致連續兩格都判成可種。

**理解自測**：只有 `[0]`，要 1 朵可以嗎？答案：可以；邊界外視為沒有花。

## 345. Reverse Vowels of a String

難度：Easy｜[英文原題](https://leetcode.com/problems/reverse-vowels-of-a-string/)｜[官方中文](https://leetcode.cn/problems/reverse-vowels-of-a-string/)

**中文題意（自行改寫）**：只把字串裡的母音順序反轉，其他字元待在原位。母音是 a/e/i/o/u，大小寫都算，交換時保留原字元大小寫。

**白話思路**：可以先收集母音再倒著填；更直接的是兩根手指：左邊找母音、右邊找母音，找到就交換，再往中間移動。

**手算**：`"radio"` 的母音依序 a、i、o。索引 1 的 a 與索引 4 的 o 交換，i 在中間不用動 → `"rodia"`。

```kotlin
class Solution {
    fun reverseVowels(s: String): String {
        val chars = s.toCharArray()
        val vowels = "aeiouAEIOU"
        var left = 0
        var right = chars.lastIndex
        while (left < right) {
            while (left < right && chars[left] !in vowels) left++
            while (left < right && chars[right] !in vowels) right--
            val temp = chars[left]
            chars[left] = chars[right]
            chars[right] = temp
            left++
            right--
        }
        return String(chars)
    }
}
```

**為什麼對**：每次配對剩下最左與最右的母音，正是反轉順序應有的對應。索引只往中間移動，時間 O(n)；複製字元陣列，空間 O(n)。

**常見錯誤**：漏大寫；忘記 `left < right`，無母音時走出邊界。

**理解自測**：`"xyz"` 怎麼辦？答案：原樣返回；兩指標會相遇，不會越界。

## 151. Reverse Words in a String

難度：Medium｜[英文原題](https://leetcode.com/problems/reverse-words-in-a-string/)｜[官方中文](https://leetcode.cn/problems/reverse-words-in-a-string/)

**中文題意（自行改寫）**：把單字的排列順序反轉，單字內的字母不反轉。輸入可能有頭尾空格或連續空格；結果只在相鄰單字間留一個空格。輸入至少有一個單字。

**白話思路**：先學清楚版：清掉頭尾空白、依空白切成單字、反轉單字清單、重新接合。不是任何題都必須手刻全部功能；要知道函式背後在做什麼。

**手算**：`"  learn   kotlin now "` → `[learn,kotlin,now]` → `[now,kotlin,learn]` → `"now kotlin learn"`。

```kotlin
class Solution {
    fun reverseWords(s: String): String {
        val words = s.trim().split(Regex("\\s+"))
        return words.reversed().joinToString(" ")
    }
}
```

**為什麼對**：切分後每個元素是一個完整單字，反轉只改元素順序；接合器保證每個間隔只有一格。時間 O(n)，空間 O(n)，n 是字串長度。這是易讀版本，不宣稱原地 O(1) 空間。

**常見錯誤**：直接 `s.reversed()` 會連字母都倒過來；只用 `split(" ")` 又不處理空元素會保留多餘空格。

**理解自測**：`"ab cd"` 的結果是 `"dc ba"` 嗎？答案：不是，是 `"cd ab"`。

## 238. Product of Array Except Self

難度：Medium｜[英文原題](https://leetcode.com/problems/product-of-array-except-self/)｜[官方中文](https://leetcode.cn/problems/product-of-array-except-self/)

**中文題意（自行改寫）**：每個位置的答案是「其他所有位置的數相乘」。不能用除法，要求線性時間。可能有零或負數；題目保證相關乘積可用 32 位元整數表示。

**白話思路**：每格重新乘一次是 O(n²)。改把「除了自己」拆成「左邊全部 × 右邊全部」。第一趟把左乘積存入答案，第二趟把右乘積乘進去。空的一邊乘積是 1，因為乘 1 不改結果。

**圖解**：輸入 `[2,3,4]`。

| 位置 | 左邊的乘積 | 右邊的乘積 | 答案 |
|---|---:|---:|---:|
| 0 | 1 | 3×4=12 | 12 |
| 1 | 2 | 4 | 8 |
| 2 | 2×3=6 | 1 | 6 |

```kotlin
class Solution {
    fun productExceptSelf(nums: IntArray): IntArray {
        val answer = IntArray(nums.size)
        var leftProduct = 1
        for (i in nums.indices) {
            answer[i] = leftProduct // 先寫，才不會乘進自己
            leftProduct *= nums[i]
        }
        var rightProduct = 1
        for (i in nums.lastIndex downTo 0) {
            answer[i] *= rightProduct
            rightProduct *= nums[i]
        }
        return answer
    }
}
```

**為什麼對**：寫入時累積值只包含索引以左或以右的元素，自己永遠沒進自己的結果。時間 O(n)；結果 O(n)，排除結果的額外空間 O(1)。

**常見錯誤**：先更新乘積才寫答案；用總乘積除自己，遇零失敗也違反要求。

**理解自測**：`[2,0,4]` 結果？答案：`[0,8,0]`，不需要為零另外寫分支。

## 334. Increasing Triplet Subsequence

難度：Medium｜[英文原題](https://leetcode.com/problems/increasing-triplet-subsequence/)｜[官方中文](https://leetcode.cn/problems/increasing-triplet-subsequence/)

**中文題意（自行改寫）**：能否挑出索引 i<j<k，且值也嚴格遞增？不用連續，但不能改原順序。要求 O(n) 時間與 O(1) 額外空間。

**白話思路**：三層迴圈可枚舉三人組，但太慢。我們只記「目前最容易當第一階的值 first」和「曾經有較小前輩的最佳第二階 second」。看到更小值就降低門檻；看到比第二階還大的值，就湊滿三階。

**手算**：`[5,1,4,2,3]`：first=5 → first=1 → second=4 → second=2 → 3>2，找到 1、2、3。

```kotlin
class Solution {
    fun increasingTriplet(nums: IntArray): Boolean {
        var first = Int.MAX_VALUE
        var second = Int.MAX_VALUE
        for (x in nums) {
            if (x <= first) {
                first = x
            } else if (x <= second) {
                second = x
            } else {
                return true
            }
        }
        return false
    }
}
```

**為什麼對**：second 被設定時，前面一定曾有比它小的值。即使之後 first 變成更晚的位置，這段歷史仍成立；因此任何後來大於 second 的值都能接成三元組。這兩個變數是存在性的證據，不一定是最後答案的同一對索引。時間 O(n)，空間 O(1)。

**常見錯誤**：用 `<` 取代 `<=`，把相等值誤認成嚴格遞增；先排序會破壞原順序。

**理解自測**：`[1,1,1]` 呢？答案 false；相等不能升階。

## 443. String Compression

難度：Medium｜[英文原題](https://leetcode.com/problems/string-compression/)｜[官方中文](https://leetcode.cn/problems/string-compression/)

**中文題意（自行改寫）**：把字元陣列中每一段連續相同字元壓成「字元＋次數」，次數是 1 時省略。直接覆寫原陣列，回傳有效長度；長度之後的內容不重要。次數超過一位時要拆成多個數字字元。

**白話思路**：`read` 找每一組的終點；`write` 指向答案下次寫入處。先看完整組才寫，不會丟掉還需要讀的資料。這裡用手動拆位數，讓額外空間維持 O(1)。

**手算**：`[b,b,b,c,d,d]`：讀完三個 b，寫 b、3；一個 c，只寫 c；兩個 d，寫 d、2。有效前段 `[b,3,c,d,2]`，回傳 5。

```kotlin
class Solution {
    fun compress(chars: CharArray): Int {
        var read = 0
        var write = 0
        while (read < chars.size) {
            val current = chars[read]
            val start = read
            while (read < chars.size && chars[read] == current) read++
            var count = read - start
            chars[write++] = current
            if (count > 1) {
                var divisor = 1
                while (count / divisor >= 10) divisor *= 10
                while (divisor > 0) {
                    chars[write++] = ('0'.code + count / divisor).toChar()
                    count %= divisor
                    divisor /= 10
                }
            }
        }
        return write
    }
}
```

**為什麼對**：一組壓縮後的長度不大於原組長度，所以寫入不會超越已讀範圍；各組串起來就是答案。時間 O(n)，額外空間 O(1)。例如 12：divisor=10，先寫 1，剩 2；divisor=1，再寫 2。

**常見錯誤**：把不連續的相同字元合併；回傳新字串而非長度；認為 12 可以放進單一 Char。

**理解自測**：`[a,b,a]` 能壓成 a2b 嗎？答案：不能，只有連續的一組才能合併。

## 283. Move Zeroes

難度：Easy｜[英文原題](https://leetcode.com/problems/move-zeroes/)｜[官方中文](https://leetcode.cn/problems/move-zeroes/)

**中文題意（自行改寫）**：直接修改陣列，把 0 全移到最後，非零元素保持原本相對順序。函式不需要回傳陣列，且不能再建立一份同樣大小的陣列。

**白話思路**：像把有人的座位往前補滿。`read` 逐格檢查，`write` 是下一個有人的座位。遇到非零就寫到前面；最後把空下來的尾段填 0。

**手算**：`[0,7,0,2]`：讀 7 寫到索引 0；讀 2 寫到索引 1；尾段索引 2、3 填零 → `[7,2,0,0]`。寫入過程暫時有重複數字沒關係，尾段稍後會清掉。

```kotlin
class Solution {
    fun moveZeroes(nums: IntArray) {
        var write = 0
        for (read in nums.indices) {
            if (nums[read] != 0) nums[write++] = nums[read]
        }
        while (write < nums.size) nums[write++] = 0
    }
}
```

**為什麼對**：非零元素依讀取順序寫入，順序不變；write 不會跑到 read 前方，因此不會蓋掉尚未讀取的值。時間 O(n)，額外空間 O(1)。

**常見錯誤**：用排序把零搬走，會改變非零元素的順序；只收集非零卻忘了尾段填零。

**理解自測**：全都是零時 write 最後是多少？答案：0，第二段會把全陣列填零。

## 392. Is Subsequence

難度：Easy｜[英文原題](https://leetcode.com/problems/is-subsequence/)｜[官方中文](https://leetcode.cn/problems/is-subsequence/)

**中文題意（自行改寫）**：判斷 s 能不能從 t 刪掉一些字元後得到。可以不連續，但保留下來的字元不能換順序。s 或 t 可能為空。

**白話思路**：s 是你要找的購物清單，t 是一路經過的貨架。只要遇到清單下一項就打勾，沒遇到就繼續走。`matched` 是已經對上幾個字，也是下一個要找的索引。

**手算**：s=`"kt"`、t=`"kotlin"`。先遇 k → matched=1；o 跳過；t → matched=2，清單全部完成，所以 true。

```kotlin
class Solution {
    fun isSubsequence(s: String, t: String): Boolean {
        var matched = 0
        for (c in t) {
            if (matched < s.length && s[matched] == c) matched++
        }
        return matched == s.length
    }
}
```

**為什麼對**：需要的字選最早出現的位置，只會替後面留更多選擇，沒有理由刻意等更晚的同字。時間 O(t.length)，空間 O(1)。

**常見錯誤**：用 `contains` 查整段子字串；忽略順序只算字數。

**理解自測**：空 s 是任何 t 的子序列嗎？答案：是，全部刪掉就得到空字串。

## 11. Container With Most Water

**中文題意（自行改寫）**：每格是一根垂直線的高度，選兩根和地面形成容器，求最大面積。寬是索引差，高只能取較矮的一根；不是計算雨水積在每個凹槽的總量。

**白話思路**：暴力枚舉兩根是 O(n²)。雙指標先選最外兩根，算面積，再移動較矮的一側。因為固定矮邊、只往內移高邊，寬縮短而水位不可能超過矮邊，沒有改善機會。

**手算**：`[2,5,4,3]`：兩端寬 3、高 2，面積 6；左邊較矮，移左到 1。此時寬 2、高 3，面積 6；移右到 2，寬 1、高 4，面積 4。最大 6。

```kotlin
class Solution {
    fun maxArea(height: IntArray): Int {
        var left = 0
        var right = height.lastIndex
        var best = 0
        while (left < right) {
            val area = minOf(height[left], height[right]) * (right - left)
            best = maxOf(best, area)
            if (height[left] <= height[right]) left++ else right--
        }
        return best
    }
}
```

**為什麼對**：每次丟掉的一側，與其內側任何另一邊搭配都不會勝過剛算過的面積；所以不會跳過尚未計算的更好答案。時間 O(n)，空間 O(1)。題目範圍下乘積可用 Int。

**常見錯誤**：面積用較高邊；寬寫成 `right-left+1`；誤以為應保留短邊。

**理解自測**：兩邊一樣高要移哪邊？答案：任一邊皆可，上面選左邊。

**中文題意（自行改寫）**：每次挑兩個加總為 k 的元素並移除，最多可以做幾次？同一元素不能重複使用；值相同但位置不同是不同元素。

**白話思路**：用字典記「還沒配到伴的人」。看到 x，就找 k-x；找得到就配成一組，庫存減一；找不到才把 x 放入庫存。也可排序加雙指標，但會多 O(n log n) 排序時間。

**手算**：`[2,4,2,4,3]`、k=6：存 2；4 找到 2 → 1 組；再存 2；4 再配 → 2 組；3 找不到另一個 3，只能留下。

```kotlin
class Solution {
    fun maxOperations(nums: IntArray, k: Int): Int {
        val waiting = HashMap<Int, Int>()
        var pairs = 0
        for (x in nums) {
            val need = k - x
            val count = waiting[need] ?: 0
            if (count > 0) {
                waiting[need] = count - 1
                pairs++
            } else {
                waiting[x] = (waiting[x] ?: 0) + 1
            }
        }
        return pairs
    }
}
```

**為什麼對**：x 的伴侶只能是 k-x，現在配掉不會搶走其他種類需要的不同伴侶。平均時間 O(n)，空間 O(n)；雜湊查找以平均 O(1) 計。

**常見錯誤**：用 Set 忘記重複值的數量；先存自己再找，讓一個 3 跟自己湊 6。

**理解自測**：`[3,3,3]`、k=6？答案：1 組，不是 3 組。

難度：Easy｜[英文原題](https://leetcode.com/problems/maximum-average-subarray-i/)｜[官方中文](https://leetcode.cn/problems/maximum-average-subarray-i/)

**中文題意（自行改寫）**：找長度恰好為 k 的連續區段，其平均值最大是多少。可有負數，k 在 1 到陣列長度之間。

**白話思路**：每格重新加 k 個值要 O(nk)。把一段想成寬度 k 的相框：向右移一格，只要扣掉離開的左端，再加上進來的右端。k 固定，找最大總和等同找最大平均。

**手算**：`[2,-1,5,3]`、k=2：第一窗 `[2,-1]` 總和 1；移動扣 2 加 5 得 4；再扣 -1 加 3 得 8。最大平均 8/2=4.0。

```kotlin
class Solution {
    fun findMaxAverage(nums: IntArray, k: Int): Double {
        var sum = 0
        for (i in 0 until k) sum += nums[i]
        var best = sum
        for (right in k until nums.size) {
            sum += nums[right] - nums[right - k]
            best = maxOf(best, sum)
        }
        return best.toDouble() / k
    }
}
```

**為什麼對**：移動時視窗中間的元素都沒變，只有一進一出；因此每個 k 長區段都被算一次。時間 O(n)，空間 O(1)。題目數值範圍下視窗總和可用 Int。

**常見錯誤**：best 從 0 開始，全負數時回傳不存在的 0；整數相除後才轉 Double，已經丟掉小數。

**理解自測**：k 等於整個陣列長度時會滑動嗎？答案：不會，只有第一個視窗。

難度：Medium｜[英文原題](https://leetcode.com/problems/max-consecutive-ones-iii/)｜[官方中文](https://leetcode.cn/problems/max-consecutive-ones-iii/)

**中文題意（自行改寫）**：二元陣列中最多可把 k 個 0 當成 1，求最長連續 1 的長度。不一定要真的修改陣列；k 可為 0。

**白話思路**：換句話說，找「至多含 k 個零」的最長視窗。右邊努力擴張；零超標時，左邊往右縮，直到合法。這次視窗長度會變，所以叫不固定長度的滑動視窗。

**手算**：`[1,0,1,0,1]`、k=1。右邊走到索引 2，視窗 `[1,0,1]` 長 3；走到 3 時有兩個零，左端先移過 1，再移過第一個 0，留下 `[1,0]`；再加末尾 1，長度又是 3。

```kotlin
class Solution {
    fun longestOnes(nums: IntArray, k: Int): Int {
        var left = 0
        var zeros = 0
        var best = 0
        for (right in nums.indices) {
            if (nums[right] == 0) zeros++
            while (zeros > k) {
                if (nums[left] == 0) zeros--
                left++
            }
            best = maxOf(best, right - left + 1)
        }
        return best
    }
}
```

**為什麼對**：零太多時，將右邊繼續加長不會變合法，只能丟掉左邊。縮完得到以 right 結尾的最長合法視窗。左右指標各最多移 n 次，即使有 while，仍是 O(n) 時間；空間 O(1)。

**常見錯誤**：只縮一次就以為合法；把 k 解讀成一定要翻 k 次。

**理解自測**：k=0 且全是 0？答案：0；合法視窗可以暫時為空。

**白話思路**：找最多一個零的視窗，刪去其中一格後就能全是 1。有零就刪零；沒有零也得刪一個 1。因此答案是合法視窗長度減一。

```kotlin
class Solution {
```

難度：Easy｜[英文原題](https://leetcode.com/problems/find-pivot-index/)｜[官方中文](https://leetcode.cn/problems/find-pivot-index/)

**中文題意（自行改寫）**：找最左邊的索引，使這格左側總和等於右側總和；自己不算在兩邊。空的一側總和算 0，找不到回傳 -1，數字可為負數。

**白話思路**：先知道全部總和 total，再一路維護左側和 left。右側不必重新加，直接用 `total-left-自己`。每個位置左右各加一次會 O(n²)，這樣只需兩趟。

**手算**：`[2,1,-1,2]`，total=4。索引 0：左 0、右 2，不同；索引 1：左 2、右 1；索引 2：左 3、右 2；索引 3：左 2、右 0，沒有，回傳 -1。另一個 `[2,1,2]` 在索引 1 左右都是 2。

```kotlin
class Solution {
    fun pivotIndex(nums: IntArray): Int {
        var total = 0
        for (x in nums) total += x
        var left = 0
        for (i in nums.indices) {
            val right = total - left - nums[i]
            if (left == right) return i
            left += nums[i] // 比較完，這格才加入下一輪左邊
        }
        return -1
    }
}
```

**為什麼對**：全部恰好分成左邊、自己、右邊；從左往右第一次成功必是最左答案。時間 O(n)，空間 O(1)。

**常見錯誤**：先加自己才比較，導致左邊錯多一格；只適用正數的「兩端加總往中間」不能直接套在可含負數的本題。

**理解自測**：`[0,0]` 回傳 0 還是 1？答案：0，要求最左。

```kotlin
class Solution {
    fun findDifference(nums1: IntArray, nums2: IntArray): List<List<Int>> {

        val onlyFirst = mutableListOf<Int>()

        for (x in first) if (x !in second) onlyFirst.add(x)
```

```kotlin
class Solution {

        val counts = HashMap<Int, Int>()
        for (x in arr) counts[x] = (counts[x] ?: 0) + 1

}
```

## 1657. Determine if Two Strings Are Close

難度：Medium｜[英文原題](https://leetcode.com/problems/determine-if-two-strings-are-close/)｜[官方中文](https://leetcode.cn/problems/determine-if-two-strings-are-close/)

**中文題意（自行改寫）**：兩個小寫字串能否透過任意次操作互換？可交換任意兩個位置；也可選兩種「已存在」的字母，把所有該字母互換。例如所有 a 換 b，同時所有 b 換 a。不能引入原本沒有的字母。

**白話思路**：換位置讓順序不重要；整批換字母讓「哪個字母拿到哪個次數」也不重要。但出現過的字母種類不能變，次數的整包組合也不能變。因此比兩件事：字母集合相同、次數排序後相同。

**手算**：`"aabbbc"` 次數 a2,b3,c1；`"abbccc"` 次數 a1,b2,c3。字母種類都是 a,b,c，次數都是 1,2,3，因此可透過整批交換與重新排列達成。

```kotlin
class Solution {
    fun closeStrings(word1: String, word2: String): Boolean {
        if (word1.length != word2.length) return false
        val a = IntArray(26)
        val b = IntArray(26)
        for (c in word1) a[c - 'a']++
        for (c in word2) b[c - 'a']++
        for (i in 0 until 26) {
            if ((a[i] == 0) != (b[i] == 0)) return false
        }
        a.sort()
        b.sort()
        return a.contentEquals(b)
    }
}
```

**為什麼對**：種類不同無法引入新字；種類相同時，整批交換可把各種次數重新分配給字母，最後用位置交換排成目標。時間 O(a+b+26 log 26)，通常寫 O(a+b)；空間 O(26)=O(1)，因字母表固定。

**常見錯誤**：只比排序後次數，會把 `"aa"` 和 `"bb"` 誤判 true；IntArray 的 `==` 不是逐格內容比較。

**理解自測**：`"aa"` 和 `"bb"` 為何 false？答案：原本沒有 b，不能選 b 來交換。

## 2352. Equal Row and Column Pairs

難度：Medium｜[英文原題](https://leetcode.com/problems/equal-row-and-column-pairs/)｜[官方中文](https://leetcode.cn/problems/equal-row-and-column-pairs/)

**中文題意（自行改寫）**：n×n 方陣裡，找「整排由左到右」等於「整欄由上到下」的配對數。內容和順序都要相同，重複的排或欄會各自產生配對。

**白話思路**：每排與每欄直接比要 O(n³)。改把每排當成字典的 key，value 記這種排出現幾次；再建立每欄的 key 去查。有三排相同，這欄就貢獻三對。

**手算**：`[[1,2],[2,1]]`。兩排是 `[1,2]`、`[2,1]`，兩欄也恰好是這兩種，所以共 2 對。

```kotlin
class Solution {
    fun equalPairs(grid: Array<IntArray>): Int {
        val counts = HashMap<List<Int>, Int>()
        for (row in grid) {
            val key = row.toList()
            counts[key] = (counts[key] ?: 0) + 1
        }
        var answer = 0
        for (column in grid.indices) {
            val key = List(grid.size) { row -> grid[row][column] }
            answer += counts[key] ?: 0
        }
        return answer
    }
}
```

**為什麼對**：List 用元素內容比較，查到的次數就是能與這欄搭配的排數。建立與雜湊每個長 n 的 key 要 O(n)，共有 O(n) 個，因此平均時間 O(n²)，空間 O(n²)。

**常見錯誤**：直接用 IntArray 當 Map key，它預設不以元素內容判等；把重複排只記一次。

**理解自測**：2×2 全部都是 1，答案？答案：4，每一排都能搭每一欄。

## 2390. Removing Stars From a String

難度：Medium｜[英文原題](https://leetcode.com/problems/removing-stars-from-a-string/)｜[官方中文](https://leetcode.cn/problems/removing-stars-from-a-string/)

**中文題意（自行改寫）**：每顆星號會把自己和左邊最近、尚未刪掉的非星號字元一起移除。輸入保證每次移除有合法對象，求最後剩下的字串。

**白話思路**：像編輯器的退格鍵。看到一般字母就加到末尾，看到星號就刪末尾。末尾正是「最近還活著的左邊字母」。這就是後進先出的堆疊；這題 StringBuilder 已足夠，不必特別造節點。

**手算**：`"ab*c*d"`：a → ab → a → ac → a → ad，答案 `"ad"`。

```kotlin
class Solution {
    fun removeStars(s: String): String {
        val stack = StringBuilder()
        for (c in s) {
            if (c == '*') stack.deleteCharAt(stack.length - 1)
            else stack.append(c)
        }
        return stack.toString()
    }
}
```

**為什麼對**：處理完前 i 個字元後，stack 就是該前綴刪除後的結果；下一字元只需新增或退格即可維持正確。時間 O(n)，空間 O(n)，末端刪除不用搬動其他字元。

**常見錯誤**：每次都掃回原字串找最近非星號，卻忘了某些字已被刪除；原地刪字串中間造成重複搬移。

**理解自測**：`"xy**"` 最後剩什麼？答案：空字串。

## 735. Asteroid Collision

難度：Medium｜[英文原題](https://leetcode.com/problems/asteroid-collision/)｜[官方中文](https://leetcode.cn/problems/asteroid-collision/)

**中文題意（自行改寫）**：每個非零整數代表小行星，絕對值是大小，正數向右、負數向左，速度相同。相撞時小的消失，一樣大兩者都消失；回傳剩下的行星順序。

**白話思路**：用堆疊保存已處理且還活著的行星。只有「左邊正、右邊負」會迎面相撞；其他組合不是遠離就是同向。新來的負數可能連續撞掉多顆正數，所以需要 while。

**手算**：`[4,2,-3]`：先存 4、2；-3 撞掉 2，自己繼續；接著撞 4，-3 較小而消失，最後 `[4]`。

```kotlin
import java.util.ArrayDeque

class Solution {
    fun asteroidCollision(asteroids: IntArray): IntArray {
        val stack = ArrayDeque<Int>()
        for (x in asteroids) {
            var alive = true
            while (alive && x < 0 && stack.isNotEmpty() && stack.peekLast() > 0) {
                val top = stack.peekLast()
                when {
                    top < -x -> stack.removeLast()
                    top == -x -> {
                        stack.removeLast()
                        alive = false
                    }
                    else -> alive = false
                }
            }
            if (alive) stack.addLast(x)
        }
        return stack.toIntArray()
    }
}
```

**為什麼對**：新行星最先可能遇到的只能是存活序列最右邊的行星；處理完這次碰撞才有資格看更左邊。每顆最多加入、移除一次，總時間 O(n)，空間 O(n)。本題數值範圍不含 Int.MIN_VALUE，因此 `-x` 安全。

**常見錯誤**：看到一正一負就碰撞，`[-2,3]` 實際在遠離；只碰撞一次便停止。

**理解自測**：`[3,-3]` 答案？空陣列，兩顆同歸於盡。

## 394. Decode String

難度：Medium｜[英文原題](https://leetcode.com/problems/decode-string/)｜[官方中文](https://leetcode.cn/problems/decode-string/)

**中文題意（自行改寫）**：像 `次數[片段]` 的編碼表示把片段重複指定次數，括號可巢狀。輸入是合法編碼，數字只代表重複次數、不當作普通文字；求展開後字串。

**白話思路**：遇左括號就像開新工作：把「外層寫到哪裡、要重複幾次」先收進堆疊，另開空白草稿。遇右括號表示內層完成，拿回外層草稿，把內層重複貼上。多位數用 `number*10+新數字` 累積。

**手算**：`"2[x3[y]]"`：外層保存次數 2；內層讀 x，再保存 `x` 與次數 3；讀 y；第一個右括號得到 xyyy；第二個右括號重複兩次，得到 `"xyyyxyyy"`。

```kotlin
import java.util.ArrayDeque

class Solution {
    fun decodeString(s: String): String {
        val counts = ArrayDeque<Int>()
        val texts = ArrayDeque<StringBuilder>()
        var current = StringBuilder()
        var number = 0
        for (c in s) {
            when {
                c in '0'..'9' -> number = number * 10 + (c - '0')
                c == '[' -> {
                    counts.addLast(number)
                    texts.addLast(current)
                    current = StringBuilder()
                    number = 0
                }
                c == ']' -> {
                    val copies = counts.removeLast()
                    val parent = texts.removeLast()
                    repeat(copies) { parent.append(current) }
                    current = parent
                }
                else -> current.append(c)
            }
        }
        return current.toString()
    }
}
```

**為什麼對**：最近打開的括號最先關閉，所以堆疊順序正合適；每次關閉都把一段完整解碼結果交還父層。令 n 是輸入長度、L 是展開長度、d 是最大巢狀深度，這個易讀版本的保守時間上界 O(n+L·d)：巢狀時可能重複複製相同內容。峰值額外空間 O(n+L)，不是 O(1)。

**常見錯誤**：每遇一個數字就覆蓋次數，12 被當成 2；開新層後忘記 number 清零；以為輸入短就一定很快，輸出可能很長。

**理解自測**：`"12[a]"` 會輸出幾個 a？答案：12。

## 933. Number of Recent Calls

難度：Easy｜[英文原題](https://leetcode.com/problems/number-of-recent-calls/)｜[官方中文](https://leetcode.cn/problems/number-of-recent-calls/)

**中文題意（自行改寫）**：實作 RecentCounter，每次 `ping(t)` 記錄一筆時間 t 的請求，回傳含這筆在內、時間落於 `[t-3000,t]` 的請求數。每次 t 嚴格遞增，左右邊界都包含。

**白話思路**：請求排隊進來，最舊的排最前面。新請求加入尾端，把前面過期的全部趕走，隊伍長度就是答案。這是先進先出的佇列；跟上一題後進先出的堆疊不同。

**手算**：依序 ping 10、100、3010、3011。數量是 1、2、3、3。到 3010，範圍從 10 起，10 還在；到 3011，範圍從 11 起，10 才被移除。

```kotlin
import java.util.ArrayDeque

class RecentCounter() {
    private val times = ArrayDeque<Int>()

    fun ping(t: Int): Int {
        times.addLast(t)
        while (times.isNotEmpty() && times.peekFirst() < t - 3000) {
            times.removeFirst()
        }
        return times.size
    }
}
```

**為什麼對**：t 嚴格遞增，所以過期請求必然集中在最前面，而且過期後永遠不再需要。q 次呼叫總時間 O(q)，每次攤銷 O(1)，但單次可能移除多筆。空間 O(w)，w 是目前視窗內請求數；本題整數時間且嚴格遞增，最多保留 3001 筆。

**常見錯誤**：用 `<= t-3000` 會把邊界那筆也刪掉；每次 ping 都重建 counter，前面的紀錄全消失。

**理解自測**：為什麼不能用堆疊末尾判過期？答案：最新的一筆在末尾，需要先丟最舊的一筆。
